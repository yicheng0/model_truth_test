# 检测任务列表顶部错误日志 Checklist

> 每项均通过运行代码或观察行为验证。

## 实现完整性

- [ ] “检测任务列表”卡片内、渠道汇总表之前显示独立的“错误日志”区域（验证：打开 `/runs`，无需滚动即可看到错误日志标题和内容）。
- [ ] 顶部标题显示当前渠道范围内的真实错误总数（验证：构造已知数量的错误分页响应，标题数量与接口 `total` 一致）。
- [ ] 每条顶部错误显示错误类型、渠道、任务名称和时间（验证：检查顶部每一行四类信息均存在）。
- [ ] 任务名称可点击并链接到对应任务详情（验证：检查链接地址为 `/runs/{runId}`，点击后进入对应详情）。
- [ ] Kiro 身份泄漏显示为“Kiro 身份泄漏”，并排在 Signature 与普通巡检异常之前（验证：混合三类错误后检查可见顺序）。
- [ ] 明确 Thinking Signature 400 拒绝显示为“Thinking Signature 无效”，并排在普通巡检异常之前（验证：混合 Signature 与普通错误后检查顺序）。
- [ ] 其他服务端真实错误统一显示为“巡检异常”，不在顶部解析或显示完整错误正文（验证：检查普通错误行和 DOM 文本）。
- [ ] 同一任务同时命中 Kiro、Signature 和普通错误时只显示一行，并使用 Kiro 类型（验证：构造重复 `runId` 的三类输入，检查条目数和类型）。
- [ ] 普通巡检异常按时间从新到旧补足高优先级异常后的剩余位置（验证：使用乱序时间输入，检查输出顺序）。
- [ ] 顶部最多显示 10 条，错误总数大于 10 时仍显示真实总数和“查看全部错误”（验证：构造 17 条错误，检查可见错误行数为 10、标题为 17）。
- [ ] 无真实错误时显示“暂无需要处理的错误”，不显示正常巡检记录（验证：错误分页 `total=0`，检查空状态和无错误行）。

## 错误口径

- [ ] 顶部错误条目只来自服务端 `errors_only=true` 响应和现有 Kiro/Signature 异常摘要（验证：网络请求和组合器测试，不读取普通任务 `failed` 状态生成错误）。
- [ ] 正常巡检不进入顶部错误总数或列表（验证：混合正常与异常响应，检查正常任务名称不出现）。
- [ ] HTTP 500、权限、额度、超时、网络和其他运营不确定性不进入顶部错误总数或列表（验证：这些记录不出现在 `errors_only=true` fixture，顶部不展示其任务名称）。
- [ ] 普通检测任务的 `failed` 状态不被自动视为真实性异常（验证：普通任务表包含 `failed` 任务，但顶部错误列表不因此增加）。
- [ ] 顶部不展示 API Key、认证头、完整错误正文、原始请求或原始响应（验证：检查响应使用轻量摘要，DOM 不包含 fixture 中的敏感正文）。

## 查询与性能

- [ ] 顶部真实错误使用独立轻量请求，固定 `page=1&page_size=10&errors_only=true`（验证：浏览器记录请求 URL 和参数）。
- [ ] 顶部查询缓存键只随渠道变化，不随下方页码或“只看错误”按钮变化（验证：切换第 6 页和错误开关，顶部请求次数不增加）。
- [ ] 顶部首屏不请求任何 `/api/runs/{id}/results` 完整详情接口（验证：E2E 网络监听详情请求数为 0）。
- [ ] 顶部查询或异常摘要延迟时，普通检测任务渠道汇总表先展示并可展开或点击（验证：为顶部接口增加延迟，检查普通表先可见且可操作）。
- [ ] 顶部真实错误请求失败时只显示局部错误和重试，普通任务表不显示整体加载失败（验证：返回 500，检查顶部局部 Alert 与普通表行仍存在）。
- [ ] Kiro/Signature 摘要失败但真实错误分页成功时，普通巡检异常仍显示，并提示高优先级分类暂未加载（验证：仅让 anomalies 接口返回 500）。
- [ ] 顶部查询按固定周期刷新，但不会因下方分页交互产生请求风暴（验证：检查 Query 配置和浏览器请求次数）。

## 交互与集成

- [ ] 点击“查看全部错误”后，下方“只看错误”按钮进入开启状态（验证：检查 `aria-pressed=true`）。
- [ ] 点击“查看全部错误”后，下方巡检页码重置为第 1 页（验证：先位于第 6 页再点击，检查请求为 `page=1` 且分页器选中 1）。
- [ ] 点击“查看全部错误”后页面滚动定位到自动巡检日志卡片（验证：检查卡片进入视口或其顶部位置接近视口）。
- [ ] “查看全部错误”保留当前渠道筛选和每页条数（验证：选择渠道 B、修改 page size 后点击，检查请求仍包含渠道 B 和原 page size）。
- [ ] 切换渠道后，顶部错误总数、条目和 Kiro/Signature 类型仅属于所选渠道（验证：在全部渠道和渠道 B 间切换，核对响应及 DOM）。
- [ ] 删除顶部命中的巡检任务后，顶部查询失效并移除对应入口（验证：执行删除并检查请求刷新、链接消失和总数减少）。
- [ ] 取消巡检任务后，顶部真实错误、下方分页和异常摘要均按需刷新（验证：检查 mutation 后三类查询失效）。
- [ ] 下方自动巡检日志仍保留渠道筛选、只看错误、分页、详情展开、行选择和批量删除（验证：执行原浏览器回归完整流程）。
- [ ] 下方现有 Kiro/Signature 全局提示保持可用，不因顶部新增区域消失或重复请求详情（验证：检查下方两类提示和网络记录）。
- [ ] 普通检测任务列表的选择、删除、展开、详情和状态展示保持现状（验证：执行普通任务表选择与展开场景）。
