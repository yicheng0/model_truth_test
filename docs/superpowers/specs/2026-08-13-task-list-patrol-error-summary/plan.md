# 检测任务列表顶部错误日志 Plan

## 架构概览

本次采用“复用现有轻量查询、前端组合摘要”的方案，不新增数据库表、迁移或完整结果请求。

页面已有两类独立轻量数据：

1. 自动巡检分页接口可以按当前渠道返回真实错误总数和最近错误任务摘要。
2. 全局异常摘要接口可以返回 Kiro 身份泄漏与明确 Thinking Signature 400 拒绝的总数和有限任务入口。

顶部错误日志增加独立查询状态：固定请求第一页、每页 10 条、只看错误，并跟随当前巡检渠道筛选。页面把 Kiro、Signature 和普通真实异常在前端去重合并：Kiro 优先，其次 Signature，最后按时间补足其他最近异常，最多展示 10 条。

```text
当前渠道筛选
  ├── 真实错误分页查询（page=1, page_size=10, errors_only=true）
  │     └── 真实错误总数 + 最近错误任务
  └── Kiro / Signature 异常摘要查询
        └── 高优先级异常总数 + 有限任务入口

两份轻量响应
  -> 去重、优先级排序、截取 10 条
  -> 检测任务列表顶部“错误日志”
  -> 查看全部错误：开启下方“只看错误”并滚动定位
```

顶部错误日志与普通检测任务列表、下方巡检分页分别使用独立查询状态。任一摘要请求延迟或失败均不阻塞普通检测任务表格。

## 核心数据结构

### 顶部错误日志条目

由现有轻量响应在页面内归一化，包含：

- `runId`: 对应巡检任务标识，用于详情链接和去重。
- `runName`: 任务名称。
- `channelId`: 渠道标识。
- `channelName`: 可读渠道名称。
- `createdAt`: 错误发生或报告生成时间。
- `kind`: `kiro_identity_leak`、`invalid_thinking_signature` 或 `patrol_error`。
- `priority`: Kiro 为最高，Signature 次之，普通真实异常最低。

顶部条目不包含完整错误正文、原始请求、原始响应或认证信息。

### 顶部错误日志摘要

- `total`: 当前渠道范围内真实错误总数，来自服务端错误分页响应。
- `items`: 合并去重后的最近错误条目，最多 10 条。
- `isLoading`: 顶部错误查询是否首次加载。
- `isPartial`: Kiro/Signature 摘要请求失败但真实错误分页仍可展示时为真。

### 错误类型映射

| 来源 | 顶部显示 | 优先级 |
|---|---|---:|
| Kiro 异常摘要 | Kiro 身份泄漏 | 1 |
| Signature 异常摘要 | Thinking Signature 无效 | 2 |
| `errors_only=true` 返回且未被前两类命中 | 巡检异常 | 3 |

普通运行状态 `failed` 不直接参与该映射；只有服务端真实错误口径命中的巡检任务才能进入顶部摘要。

## 核心接口

### 真实错误分页

复用：

```text
GET /api/runs/patrol?page=1&page_size=10&errors_only=true&channel_id={可选}
```

用途：

- 提供当前渠道范围内真实错误总数。
- 提供最近 10 条真实错误的轻量任务信息。
- 保持数据库错误过滤、计数和分页，不加载完整证据。

### 高优先级异常摘要

复用：

```text
GET /api/runs/patrol/anomalies?channel_id={可选}
```

用途：

- 提供 Kiro 与明确 Signature 400 的总数和任务入口。
- 为顶部错误日志提供高优先级错误类型。

### 页面查询封装

前端继续通过现有 API 客户端调用上述接口，不增加第二套请求协议。顶部真实错误查询使用独立缓存键，包含当前渠道，不包含下方页码和“只看错误”状态。

## 模块设计

### 顶部错误摘要组合器

**职责：**

- 接收真实错误分页和异常摘要两份轻量数据。
- 将 Kiro、Signature 转为高优先级条目。
- 按 `runId` 去重，避免同一任务重复展示。
- 先放置 Kiro，再放置 Signature，再以最近错误补足至 10 条。
- 输出稳定、可单元测试的摘要结果。

**依赖：** 现有巡检列表类型、异常摘要类型和日期字段。

**边界：**

- 同一任务同时包含 Kiro 和 Signature 时只占一行，显示优先级更高的 Kiro；完整详情仍可查看两类证据。
- 异常摘要接口失败时，仍展示真实错误分页中的普通“巡检异常”，并显示轻量的局部加载失败提示。
- 真实错误分页失败时，顶部区域显示局部错误和重试，不影响普通任务表。

### 顶部错误日志视图

**职责：**

- 放置在“检测任务列表”卡片内、批量选择工具栏之前。
- 使用单层紧凑列表或紧凑表格展示渠道、任务、错误类型和时间。
- 标题展示真实错误总数。
- 每条任务名称链接到对应详情页。
- 无错误时显示简洁空状态。
- 超过 10 条时显示“查看全部错误”。

**布局：**

- 不使用多层嵌套卡片。
- 错误类型使用稳定的危险色标签；渠道和时间使用次级文本。
- 默认最多 10 行，避免顶部无限增长。

### 查看全部错误联动

**职责：**

用户点击“查看全部错误”时：

1. 将下方自动巡检日志的“只看错误”切换为开启。
2. 将下方巡检页码重置为第 1 页。
3. 保留当前渠道筛选。
4. 滚动到下方自动巡检日志卡片。

自动巡检卡片提供稳定页面锚点或元素引用，避免通过不稳定的文字或 DOM 层级定位。

### 查询刷新与失效

**职责：**

- 顶部真实错误查询以固定间隔刷新，刷新周期与异常摘要保持一致。
- 切换渠道时，同时刷新顶部真实错误和高优先级异常摘要。
- 删除或取消巡检任务后，同时失效顶部错误查询、下方巡检分页和异常摘要。
- 下方切换页码或“只看错误”不触发顶部查询重复请求。

## 模块交互

### 页面首次加载

```text
普通任务查询 --------------------------> 检测任务渠道汇总表
顶部真实错误查询 ----┐
异常摘要查询 --------┴-> 摘要组合器 -> 顶部错误日志
下方巡检分页查询 ----------------------> 自动巡检日志表格
```

三条数据链路互不等待。普通任务查询返回后即可展示检测任务表；顶部错误日志可随后独立出现。

### 渠道切换

```text
选择渠道
  -> 下方巡检分页回到第 1 页并刷新
  -> 顶部真实错误查询刷新
  -> Kiro / Signature 摘要刷新
  -> 顶部仅展示该渠道错误
```

### 查看全部错误

```text
点击“查看全部错误”
  -> onlyPatrolErrors = true
  -> patrolPage = 1
  -> 滚动到自动巡检日志
  -> 下方展示当前渠道的全部错误分页
```

### 删除或取消

```text
操作成功
  -> 失效普通任务查询
  -> 失效顶部真实错误查询
  -> 失效下方巡检分页
  -> 失效异常摘要
  -> 已删除条目从顶部和下方消失
```

## 技术决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 顶部数据来源 | 复用巡检错误分页和异常摘要 | 已具备数据库过滤与轻量响应，避免新增全量扫描接口 |
| 顶部查询状态 | 独立 Query | 不受下方页码影响，也不阻塞普通任务表 |
| 高优先级错误识别 | 使用现有 Kiro/Signature 摘要 | 保持已验证的异常边界，不在前端重新解析完整证据 |
| 普通错误类型 | 统一显示“巡检异常” | 顶部不加载完整证据，避免暴露正文或制造新的分类口径 |
| 展示数量 | 最多 10 条 | 满足快速排查，同时控制顶部高度和请求大小 |
| 同任务多异常 | 按 Kiro、Signature、普通异常优先级去重 | 保持列表紧凑；完整证据交给详情页 |
| 查看全部 | 开启下方错误筛选并滚动定位 | 复用现有分页、渠道筛选、详情和删除能力 |
| 后端变更 | 默认不新增接口 | 当前接口已满足数据、性能和安全要求 |
| 失败处理 | 顶部局部错误，不影响主体 | 符合摘要不得阻塞检测任务列表的要求 |
