# 检测任务列表顶部错误日志 Tasks

## 文件清单

| 操作 | 文件 | 职责 |
|---|---|---|
| 修改 | `frontend/src/runsUtils.ts` | 定义顶部错误条目并组合、排序、去重、限量 |

## T1: 建立顶部错误组合器失败测试

**文件：** `frontend/src/runsUtils.test.ts`
**依赖：** 无

**步骤：**

1. 增加构造轻量巡检错误分页和 Kiro/Signature 异常摘要的测试数据。
2. 编写测试：Kiro 条目排在 Signature 和普通巡检异常之前。
3. 编写测试：同一 `runId` 同时存在 Kiro、Signature 和普通错误时仅保留一条，并使用 Kiro 类型。
4. 编写测试：普通错误按 `created_at` 从新到旧补足列表。
5. 编写测试：返回条目最多 10 条，但 `total` 保留服务端真实错误总数。
6. 编写测试：正常运行、运营故障或不在错误分页响应中的任务不会被组合器凭运行状态加入。
7. 运行测试并确认因组合器尚不存在而失败。

**验证：** 运行 `./node_modules/.bin/vitest run src/runsUtils.test.ts`，期望新增用例失败且失败原因指向缺少顶部错误组合行为。

## T2: 实现顶部错误条目组合器

**文件：** `frontend/src/runsUtils.ts`，必要时 `frontend/src/types.ts`
**依赖：** T1

**步骤：**

1. 定义 `PatrolTopErrorKind`，包含 Kiro、Signature 和普通巡检异常三类。
2. 定义紧凑条目字段：任务标识、任务名称、渠道、时间、类型和优先级。
3. 实现 Kiro 异常摘要条目归一化。
4. 实现 Signature 异常摘要条目归一化。
5. 实现真实错误分页条目归一化，普通类型固定为“巡检异常”。
6. 按 Kiro、Signature、普通错误的顺序合并，并以任务标识去重。
7. 普通错误按创建时间从新到旧排列，高优先级组内保持接口返回的稳定顺序。
8. 最多返回 10 条，同时保留错误分页响应中的真实总数。
9. 不解析或返回完整证据、错误正文、Request ID 或原始响应。
10. 运行 T1 测试并修正至全部通过。

**验证：** 运行 `./node_modules/.bin/vitest run src/runsUtils.test.ts`，期望全部通过。

## T3: 建立顶部错误日志浏览器失败场景

**文件：** `frontend/e2e/runs-pagination.mjs`
**依赖：** T2

**步骤：**

1. 记录顶部错误分页请求与下方巡检分页请求，按查询参数区分两者。
2. 为顶部错误分页返回超过 10 条的真实总数和最近 10 条摘要。
3. 为异常摘要返回跨页 Kiro 与 Signature 条目，并包含与普通错误重复的任务标识。
4. 增加断言：页面首屏在“检测任务列表”区域可见“错误日志”和真实总数。
5. 增加断言：顶部仅显示 10 条且重复任务只出现一次。
6. 增加断言：Kiro 与 Signature 标签可见，正常和运营记录不出现。
7. 增加断言：点击顶部任务名称进入对应 `/runs/{runId}` 链接。
8. 增加断言：点击“查看全部错误”后，下方“只看错误”开启、页码为 1，并滚动到自动巡检日志区域。
9. 增加断言：切换下方页码或错误开关不会额外触发顶部查询。
10. 增加延迟或失败 fixture，断言普通检测任务渠道表先于顶部摘要可见并仍可操作。
11. 运行脚本并确认因顶部视图尚不存在而失败。

**验证：** 运行 `node e2e/runs-pagination.mjs`，期望新增顶部错误断言失败，原有分页断言继续执行到相应位置。

## T4: 接入独立顶部真实错误查询

**文件：** `frontend/src/pages/Runs.tsx`
**依赖：** T2、T3

**步骤：**

1. 新增独立查询，固定请求 `page=1`、`page_size=10`、`errors_only=true`。
2. 查询缓存键只包含“顶部错误摘要”和当前渠道，不包含下方页码或错误开关。
3. 当前渠道为全部时不传渠道参数；指定渠道时与下方筛选保持一致。
4. 设置 60 秒定时刷新，与现有 Kiro/Signature 摘要刷新周期一致。
5. 使用 T2 组合器计算顶部错误总数与最多 10 条条目。
6. 确保普通检测任务查询、顶部错误查询、异常摘要查询和下方巡检分页互不等待。

**验证：** 运行 `./node_modules/.bin/vitest run src/runsUtils.test.ts` 和 `./node_modules/.bin/tsc -b`，期望通过。

## T5: 实现检测任务列表顶部错误日志视图

**文件：** `frontend/src/pages/Runs.tsx`
**依赖：** T4

**步骤：**

1. 在“检测任务列表”卡片中、批量选择工具栏之前插入“错误日志”区域。
2. 标题显示 `错误日志（真实总数）`。
3. 使用单层紧凑列表或小型表格展示错误类型标签、渠道、任务名称和时间。
4. 任务名称使用详情链接 `/runs/{runId}`。
5. Kiro、Signature 和普通巡检异常使用可区分的稳定标签文案。
6. 顶部错误首次加载时只显示局部加载状态，不把普通检测任务表设为 loading。
7. 顶部错误查询失败时显示局部错误和重试按钮，普通检测任务表保持可用。
8. 异常摘要查询失败但错误分页成功时继续展示普通错误，并显示简短的“高优先级分类暂未加载”提示。
9. 真实错误总数为 0 时显示“暂无需要处理的错误”，不渲染错误行。
10. 总数大于展示条目数时显示“查看全部错误”。

**验证：** 运行 `./node_modules/.bin/tsc -b`，期望类型检查通过；运行 `node e2e/runs-pagination.mjs`，期望顶部展示断言推进到查看全部联动。
