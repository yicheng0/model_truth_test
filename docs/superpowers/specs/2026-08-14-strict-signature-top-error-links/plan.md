# 顶部巡检异常严格分类与直达详情 Plan

## 架构概览

本次把顶部错误日志从“通用错误分页 + 专用异常摘要”的混合数据源，收敛为只使用现有严格异常摘要接口。

服务端继续扫描当前渠道范围内每个巡检任务的最新报告，但只识别两类证据明确的异常：

1. Kiro 身份泄漏。
2. 明确包含 `Invalid signature in thinking block` 的 Thinking Signature 拒绝。

服务端在同一次摘要计算中生成：

- 两个现有分类组，供下方 Kiro 和 Signature 提示继续使用。
- 去重后的严格异常总数。
- 按优先级和时间排列的顶部异常条目，最多 10 条。

前端顶部区域不再请求 `errors_only=true` 的通用巡检分页，也不再补入“巡检异常”。顶部总数、条目、空状态和失败状态全部来自严格异常摘要。任务名称继续链接到对应详情页。

```text
当前渠道筛选
  -> GET /api/runs/patrol/anomalies
       -> 最新巡检报告证据
       -> Kiro 明确身份泄漏
       -> HTTP 400 + Invalid signature in thinking block
       -> 按任务去重、Kiro 优先、组内按时间倒序
       -> strict_total + strict_items（最多 10 条）
          ├── 检测任务列表顶部错误日志
          └── 下方 Kiro / Signature 异常提示

通用 GET /api/runs/patrol?errors_only=true
  -> 仅服务下方历史日志筛选
  -> 不再参与顶部异常统计或展示
```

## 核心数据结构

### 严格异常条目

在现有巡检异常条目的轻量字段基础上增加异常类型：

- `run_id`: 巡检任务标识，用于详情链接和任务级去重。
- `run_name`: 任务名称。
- `channel_id`: 渠道标识。
- `channel_name`: 渠道名称。
- `created_at`: 异常报告或任务创建时间。
- `kind`: `kiro_identity_leak` 或 `invalid_thinking_signature`。
- `request_ids`: 已脱敏的有限请求标识，保留给现有下方摘要使用；顶部不渲染。
- `http_status`: Signature 明确拒绝时为 400；Kiro 可为空。
- `stage`: 身份或 Signature 发生阶段。

该结构不包含完整错误正文、原始请求、原始响应或认证信息。

### 严格异常摘要

扩展现有异常摘要响应：

- `strict_total`: 当前渠道范围内，按 `run_id` 去重后的 Kiro 或明确 Signature 异常任务总数。
- `strict_items`: Kiro 优先、Signature 次之、同类按时间从新到旧的去重条目，最多 10 条。
- `kiro_identity_leak`: 保留现有分类总数和有限任务入口。
- `invalid_thinking_signature`: 保留现有分类总数和有限任务入口。

`strict_total` 不直接相加两个分类计数，避免同一任务同时命中 Kiro 和 Signature 时重复统计。

## 核心接口

### 巡检严格异常摘要

复用并向后兼容扩展：

```text
GET /api/runs/patrol/anomalies?channel_id={可选}
```

响应增加：

```text
strict_total: number
strict_items: StrictPatrolAnomalyEntry[]
```

用途：

- 为顶部错误日志提供唯一数据源。
- 为下方 Kiro 和 Signature 提示提供现有分类组。
- 统一当前渠道范围、严格判定、任务去重和总数口径。

服务端判定边界：

- Kiro：沿用现有明确身份自报判定。
- Signature：必须匹配明确错误文本 `Invalid signature in thinking block`，并保留 HTTP 400 约束。
- `signature_ok=null`、HTTP 403 渠道禁用、网络、超时、HTTP 5xx、权限、额度、无可用渠道或账号均不进入严格摘要。

### 通用巡检分页

继续保留：

```text
GET /api/runs/patrol
```

用途不变：为下方自动巡检日志提供分页、渠道筛选、通用错误筛选和删除范围。该接口不再为顶部错误日志供数。

## 模块设计

### 服务端严格异常组合器

**职责：**

- 从当前渠道范围内的最新巡检报告提取两类明确异常。
- 分别维护 Kiro 与 Signature 分类组。
- 将两类候选按任务标识去重，Kiro 覆盖同任务的 Signature。
- Kiro 组优先，组内按时间倒序；之后追加 Signature 组并按时间倒序。
- 返回真实去重总数及最多 10 条顶部条目。

**依赖：** 最新巡检报告、现有 Kiro 判定、现有明确 Signature 错误匹配、渠道信息。

**边界：**

- 不读取通用失败状态或低评分生成严格异常。
- 历史报告即使残留 `signature_interop_failed` 标签，只要没有明确错误文本和 HTTP 400，也不进入 Signature 组。
- 403“渠道已被禁用”即使历史报告等级较低，也不进入严格摘要。

### 前端顶部异常组合器

**职责：**

- 将服务端 `strict_items` 映射为顶部紧凑行。
- 只接受 Kiro 与 Signature 两类，不定义通用“巡检异常”类型。
- 保持服务端顺序，不再从通用错误分页补足。
- 使用 `strict_total` 作为标题数量。

**边界：**

- 不解析完整错误正文判断异常类型。
- 不使用普通运行的 `failed` 状态、`display_state` 或通用分页总数。
- 不返回 Request ID、原始响应或错误正文给顶部视图。

### 顶部错误日志视图

**职责：**

- 展示错误类型、渠道、任务名称和时间。
- 任务名称链接到 `/runs/{run_id}`。
- 无严格异常时显示“暂无需要处理的错误”。
- 摘要请求失败时只显示局部错误，普通检测任务表保持可用。
- 移除通用“巡检异常”标签。

顶部与下方异常提示共享同一查询，不再发起独立顶部通用错误请求。若严格异常超过顶部展示数量，“查看全部异常”只滚动到下方严格异常提示区域，不开启可能包含其他通用错误的“只看错误”筛选。

### 下方异常提示

**职责：**

- 继续分别展示 Kiro 身份泄漏与 Thinking Signature 无效。
- 每个任务入口保持可点击并进入任务详情。
- 与顶部共享严格摘要响应，避免同一条 403 在不同区域出现不同分类。

### 查询刷新与失效

**职责：**

- 严格异常摘要继续跟随当前渠道筛选，并按固定周期刷新。
- 删除或取消任务后失效异常摘要与下方巡检分页。
- 下方页码、每页数量及“只看错误”切换不改变严格异常查询缓存键。
- 移除不再需要的顶部通用错误查询及其 mutation 失效调用。

## 模块交互

### 页面首次加载

```text
普通任务查询 --------------------------> 检测任务渠道汇总表
严格异常摘要查询 ----------------------> 顶部错误日志
                                   └---> 下方 Kiro / Signature 提示
下方巡检分页查询 ----------------------> 自动巡检历史表
```

三条链路互不等待。严格摘要延迟或失败不影响普通任务表与下方分页。

### 渠道切换

```text
选择渠道
  -> 下方巡检分页回到第 1 页
  -> 严格异常摘要按该渠道重新查询
  -> 顶部总数、顶部条目和下方两类提示同步收窄
```

### 点击异常

```text
点击顶部或下方异常任务名称
  -> 进入 /runs/{run_id}
  -> 详情页按需加载完整结果
  -> 查看 Signature 请求日志、HTTP 状态和脱敏证据
```

列表首屏不会提前加载任务详情。

### 运营故障

```text
HTTP 403 渠道已被禁用 / 网络 / 超时 / 5xx / 权限 / 额度
  -> 保留在任务详情和下方历史记录中
  -> 不进入 strict_total
  -> 不进入 strict_items
  -> 不显示 Thinking Signature 无效
```

## 技术决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 顶部数据源 | 只使用严格异常摘要接口 | 从源头排除通用失败，避免前后端口径漂移 |
| 严格总数 | 服务端按任务标识去重计算 | 两类计数直接相加会重复统计同时命中的任务 |
| 顶部条目 | 服务端返回已排序的最多 10 条 | 保证截断后仍符合 Kiro 优先和任务级去重 |
| Signature 判定 | HTTP 400 且明确匹配错误文本 | 只有该证据能证明 Signature 被协议层明确拒绝 |
| 历史运营故障 | 展示于历史与详情，不进入顶部 | 保留诊断证据，同时避免真实性误报 |
| 详情入口 | 使用任务标识链接到现有详情页 | 无需新增路由或提前加载完整证据 |
| 查看更多 | 滚动到下方严格异常提示，不开启通用错误筛选 | 通用筛选可能包含不属于顶部严格口径的其他记录 |
| 数据库 | 不迁移、不回写历史报告 | 当前严格摘要可在读取现有证据时正确解释历史数据 |
