# 顶部巡检异常严格分类与直达详情 Spec

## 背景

运行记录页目前会在顶部错误日志及下方自动巡检区域提示巡检异常。实际使用中，HTTP 403“渠道已被禁用”这类运营故障仍可能通过通用错误结果进入顶部错误日志，使用户误以为发生了 Thinking Signature 异常。

Thinking Signature 异常必须具有明确证据：上游返回 `Invalid signature in thinking block`。渠道禁用、权限、网络、超时、服务端错误、配额不足等仅说明当次请求未成功，不能作为 Signature 无效证据。

此外，异常提示应直接提供对应任务入口，用户点击后即可查看该次巡检的完整请求日志和证据，不需要再到下方长列表中重新搜索。

## 目标

- 顶部异常日志只展示证据明确、需要关注的协议或身份异常。
- 只有明确出现 `Invalid signature in thinking block` 时才报告 Thinking Signature 无效。
- HTTP 403“渠道已被禁用”和其他运营故障不进入顶部异常日志或 Signature 异常数量。
- 每条顶部异常可直接进入对应巡检任务详情。

## 功能需求

- F1: 顶部错误日志只展示 Kiro 身份泄漏和明确的 Thinking Signature 无效，不再展示来源不明确的通用“巡检异常”。
- F2: Thinking Signature 无效必须以响应内容明确出现 `Invalid signature in thinking block` 为判定条件，不得仅凭失败状态、低评分、历史标签或其他错误文案判定。
- F3: HTTP 403“渠道已被禁用”，以及网络、超时、HTTP 5xx、权限、额度、无可用渠道或账号等运营故障，不进入顶部错误总数和错误列表。
- F4: 顶部每条异常展示异常类型、渠道、任务名称和发生时间，任务名称可点击并直接进入该次巡检任务详情。
- F5: 顶部异常按 Kiro 身份泄漏优先、Thinking Signature 无效次之排列；同一任务同时命中两类时只展示一条，并优先显示 Kiro 身份泄漏。
- F6: 顶部异常总数与当前严格异常口径一致，不再沿用包含其他通用错误的数量。
- F7: 没有 Kiro 或明确 Signature 异常时，顶部显示“暂无需要处理的错误”，下方历史巡检及详情证据仍可正常查看。
- F8: 下方已有的 Kiro 与 Thinking Signature 异常提示继续提供可点击的任务入口，并与顶部采用相同判定口径。

## 非功能需求

- N1: 顶部异常展示继续使用轻量摘要，不为列表中的每条任务加载完整请求或响应。
- N2: 顶部异常查询失败或延迟时，不阻塞普通检测任务列表和下方自动巡检日志。
- N3: 顶部不展示完整错误正文、原始请求、原始响应、认证信息或 API Key；完整证据只在任务详情中展示。
- N4: 本次只收紧异常展示与计数口径，不修改巡检执行周期、渠道状态、评分或报告历史数据。

## 不做的事

- 不把 HTTP 403“渠道已被禁用”改成真实性或协议异常。
- 不删除任务详情中的 Signature 请求日志或运营故障证据。
- 不自动启用、禁用或重试渠道。
- 不修改 Kiro 身份泄漏的现有判定规则。
- 不新增数据库迁移、队列或新的巡检任务类型。
- 不清理或重写历史报告；页面按严格规则解释现有及新产生的数据。

## 验收标准

- AC1: 构造 HTTP 403 且错误为“渠道已被禁用”的巡检记录后，顶部错误总数不增加，列表中不出现该任务，也不出现“Thinking Signature 无效”。
- AC2: 构造网络、超时、HTTP 5xx、权限、额度或无可用渠道的巡检记录后，顶部错误总数和列表均不增加。
- AC3: 构造明确包含 `Invalid signature in thinking block` 的巡检记录后，顶部显示“Thinking Signature 无效”，且数量增加一条。
- AC4: 点击顶部 Signature 或 Kiro 异常的任务名称后，直接进入对应 `/runs/{任务标识}` 详情页，可查看该次请求日志。
- AC5: 同一任务同时命中 Kiro 和明确 Signature 异常时，顶部只显示一条“Kiro 身份泄漏”。
- AC6: 只有运营故障或没有异常时，顶部显示“暂无需要处理的错误”，普通任务列表和下方巡检日志仍可正常使用。
- AC7: 下方 Kiro 和 Thinking Signature 异常提示中的任务入口仍可点击，并且不会把 403 渠道禁用显示为 Signature 异常。
- AC8: 顶部首屏不请求任何任务完整结果接口，页面不展示完整错误正文或敏感字段。
