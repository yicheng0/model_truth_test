# 自动巡检日志分页交互修复 Spec

## 背景

自动巡检日志分页器能够显示页码和每页条数菜单，但用户实际点击后，表格可见日志没有可靠地随页码或每页条数变化。上一轮修复只验证了分页计算函数，没有验证真实表格交互，因此自动化通过不能证明页面功能可用。

## 方案选择

- 方案 A（采用）：页面明确计算并渲染当前页日志，分页器只负责修改页码和每页条数；增加真实组件交互测试。分页数据流单一，容易验证，不依赖表格组件内部隐式分页状态。
- 方案 B：继续把完整日志交给表格内部分页，只补充回调修复。改动较小，但当前问题正发生在这层隐式状态协作中，后续筛选和轮询刷新仍容易失效。
- 方案 C：改为后端分页。适合数据量很大时使用，但会扩大接口和后端范围，不适合本次交互缺陷回修。

## 目标

- 让页码、上一页、下一页和每页条数选择真实控制自动巡检日志的可见行。
- 让筛选、轮询刷新和删除后的页码保持有效，不出现显示页码变化但内容不变。
- 用真实页面组件交互测试和浏览器点击验收覆盖该功能。

## 功能需求

- F1: 点击任意有效页码后，表格只显示该页对应的日志，且与切换前日志不同。
- F2: 选择 10、20、50 或 100 条/页后，可见日志数量按选择值变化；不足所选数量时显示全部剩余日志。
- F3: 更改每页条数后回到第一页，页码、总页数和可见日志保持一致。
- F4: 切换渠道筛选、轮询获得新日志或删除日志后，当前页自动限制在有效范围内，不出现空白无效页。
- F5: 分页只改变当前可见行，不改变日志排序、总数、渠道筛选范围、选中删除范围和详情操作。

## 非功能需求

- N1: 不改后端运行记录接口和数据库结构，继续使用当前已加载日志集合。
- N2: 分页的数据切片只有一个负责方，避免页面状态和表格内部状态重复分页或互相覆盖。
- N3: 增加覆盖真实分页器点击和表格行变化的组件级测试，不能只测试分页纯函数。
- N4: 必须在能确认页面身份的实际 `/runs` 页面完成浏览器点击验收后，才能宣布分页修复完成。
- N5: 保留用户当前未提交的 Claude Code 前端改动，不覆盖或混入本次修复。

## 不做的事

- 不改为服务端分页。
- 不修改普通检测任务列表、渠道总览或其他表格的分页。
- 不改变批量删除权限和后端保护规则。
- 不以页大小下拉框显示了新数值代替可见日志确实变化的验收。

## 验收标准

- AC1: 准备至少 25 条巡检日志，从第 1 页切到第 2 页后，可见日志 ID 与第 1 页不同；再返回第 1 页，恢复原日志。
- AC2: 依次选择 10 条/页和 20 条/页，表格分别显示 10 条和 20 条日志，并且总页数同步变化。
- AC3: 在较后页切换每页条数或渠道筛选后，页码回到 1，表格不为空且内容属于当前筛选范围。
- AC4: 删除当前页日志或轮询刷新导致总数变化后，页码仍有效，表格显示最后一个有效页的数据。
- AC5: 组件级测试通过真实点击分页器验证可见行变化；现有分页纯函数、筛选、删除范围、前端全量测试和构建均通过。
- AC6: 在确认身份的实际 `/runs` 页面重复 AC1 至 AC3，观察结果与组件测试一致后才可完成验收。
