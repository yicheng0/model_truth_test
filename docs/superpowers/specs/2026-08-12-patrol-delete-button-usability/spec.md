# 自动巡检删除入口易用性优化 Spec

## 背景

自动巡检日志当前提供“删除已选”和“删除全部已结束”两种删除操作。日志工具栏空间不足时，按钮文字会被截断；未选择日志时“删除已选”按钮置灰但缺少明确反馈，用户容易误以为删除功能失效。删除能力本身和后端接口已经存在，本次只优化操作入口和反馈。

## 目标

- 让两种删除操作在常见桌面宽度和较窄页面宽度下都完整可见、可点击。
- 让用户能立即知道当前可以删除多少条，以及“删除已选”为什么暂不可用。
- 保持现有删除安全边界：只删除已结束日志，未结束日志不被删除。

## 功能需求

- F1: 自动巡检日志工具栏中的筛选、错误过滤和删除操作应支持换行或自适应排列，按钮文字不得被容器裁切。
- F2: “删除已选”入口应显示当前已选择且可删除的日志数量；没有可删除选择时，应明确提示先勾选已结束日志，而不是让用户猜测按钮为何不可用。
- F3: “删除全部已结束”入口应显示当前筛选范围内可删除的日志数量，并在按渠道或只看错误筛选后同步更新数量和确认文案。
- F4: 删除确认弹窗应明确删除对象、数量及未结束日志会被跳过；确认删除后，列表、分页和选择状态应同步刷新。

## 非功能需求

- N1: 不改变现有后端删除接口、权限校验、关联结果/报告/告警清理和未结束日志保护规则。
- N2: 保持现有中文界面、Ant Design 交互风格和无障碍标签；按钮在键盘操作下仍可访问。
- N3: 新增交互应有自动化测试覆盖，不能引入额外网络请求或改变分页查询语义。

## 不做的事

- 不新增删除接口、回收站或撤销删除功能。
- 不修改普通检测任务的删除入口。
- 不扩大“删除全部”的范围，不删除 pending/running 状态日志。
- 不重新设计自动巡检日志表格、筛选条件或分页组件。

## 验收标准

- AC1: 在窄窗口或工具栏空间不足时，筛选和删除控件完整显示，删除按钮文字不被截断，且每个控件仍可点击。
- AC2: 未勾选可删除日志时，“删除已选”显示为不可执行状态并提供“请先勾选已结束日志”的可观察提示；勾选一条或多条已结束日志后，按钮显示对应数量并可打开确认弹窗。
- AC3: 切换渠道或“只看错误”后，“删除全部已结束”显示的数量和确认弹窗内容与当前筛选范围一致；数量为零时不会触发删除操作。
- AC4: 确认删除后，已删除日志从列表消失，分页总数和已选状态同步更新；pending/running 日志仍保留。
- AC5: 现有前端单元测试、分页/筛选端到端测试和生产构建全部通过。
