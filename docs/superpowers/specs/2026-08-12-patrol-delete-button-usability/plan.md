# 自动巡检删除入口易用性优化 Plan

## 架构概览

保留现有巡检列表和批量删除路由，在巡检分页响应中兼容性增加当前筛选范围的可删除数量摘要；前端调整自动巡检日志卡片的操作栏、删除数量计算和确认反馈。删除操作继续通过现有批量删除 mutation 执行，成功后失效巡检列表、普通运行列表和报告查询，避免引入新的删除数据链路。

操作栏拆分为两个可自适应区域：筛选区域包含渠道选择和错误过滤；删除区域包含“删除已选”和“删除当前范围”。删除区域允许换行，按钮设置稳定的不可压缩尺寸，避免卡片宽度不足时文字被裁切。

## 核心数据结构

### `PatrolDeleteSummary`

前端根据巡检分页响应和当前选择派生以下状态；后端仅新增 `deletable_count` 摘要字段：

- `selectedDeletableCount`: 当前选中且状态为已结束的日志数量。
- `filteredDeletableCount`: 当前渠道和错误筛选条件下可删除日志数量。
- `hasSelectedRows`: 当前是否存在选中日志，包含未结束日志。
- `deleteScopeLabel`: 当前删除范围的人类可读名称，用于按钮和确认文案。

对于服务端分页结果，`filteredDeletableCount` 直接使用列表接口返回的 `deletable_count`，不以包含运行中日志的 `total` 代替；“只看错误”模式下沿用服务端错误筛选结果。为保证“删除全部”实际范围和显示数量一致，点击确认时继续按当前筛选条件分批获取完整 ID 集合，再执行现有批量删除。

## 核心接口

### `api.patrolRuns`

保持现有查询参数不变，在响应中追加 `deletable_count`，表示当前渠道与错误筛选范围内状态不为 pending/running 的日志总数。继续提供当前页面数据、总数、错误总数和筛选后的结果。新增字段为向后兼容扩展，删除按钮不增加额外的轮询或详情请求。

### `api.deleteRuns`

保持现有批量删除请求、权限头和返回结构不变。前端在确认后传入当前选择或当前筛选范围中已结束日志的 ID 集合。

## 模块设计

### `Runs.tsx` 自动巡检操作栏

**职责：** 根据当前页面选择和筛选状态渲染可执行数量、按钮状态、无障碍提示和确认弹窗。

**设计：**

- 将卡片 `extra` 内的控件包裹为带语义 class 的自适应工具栏，筛选和删除区域分别允许换行。
- “删除已选”按钮文案包含可删除数量；没有可删除选择时保持禁用，并通过 `Tooltip` 或等效可观察提示说明“请先勾选已结束日志”。
- “删除当前范围”按钮文案包含当前范围及数量；数量为零时禁用。
- 确认描述使用同一份派生数量和范围标签，明确已结束日志、关联结果/报告/告警以及未结束日志跳过规则。
- 筛选变化时保留现有回到第 1 页行为，并清理当前筛选范围外的行选择，避免显示过期选择数量。

### 后端巡检列表摘要

**职责：** 在现有渠道和错误筛选范围内统计可删除日志数量。

**设计：**

- 非错误筛选使用数据库聚合统计状态不为 pending/running 的记录。
- 错误筛选复用已构造的异常摘要集合，并统计其中已结束记录，不额外加载完整结果。
- `deletable_count` 与 `total`、`error_count` 一并返回，空结果返回 0。

### `styles.css` 工具栏布局

**职责：** 保证桌面窄宽度下控件可见、可点击和可换行。

**设计：**

- 为巡检操作栏增加 `display: flex`、`flex-wrap: wrap`、合理的行列间距和 `min-width: 0`。
- 删除按钮区域设置可伸缩但不裁切的按钮宽度，长文案允许自然换行或在更窄宽度下切换为短文案加 Tooltip。
- 不改变全局按钮样式，不影响普通检测任务卡片。

### `runsUtils.ts`

**职责：** 提供纯函数计算选择数量、可删除数量和删除范围文案（仅在现有工具函数模式适合时新增）。

**设计：**

- 复用现有 `isTerminalRun`、`deletablePatrolRunIds` 等规则，避免重复定义 pending/running 判断。
- 为数量和范围计算补充纯函数测试，覆盖空选择、只选未结束、混合选择、渠道筛选和错误筛选。

### `runs-pagination.mjs`

**职责：** 覆盖删除入口的真实页面交互。

**设计：**

- 为批量删除接口增加路由拦截和请求记录。
- 验证默认状态下删除已选不可执行且有提示。
- 勾选已结束行后验证数量、确认弹窗和批量删除请求 ID。
- 验证渠道/错误筛选后“删除当前范围”数量与范围文案更新。
- 验证窄视口下按钮文本完整可见，确认删除后日志消失、分页总数刷新、未结束日志保留。

## 模块交互

```text
用户筛选渠道/错误
  -> patrolRuns 查询返回当前范围摘要
  -> Runs 派生可删除数量和范围文案
  -> 删除按钮自适应布局并更新状态

用户勾选已结束日志
  -> 选择状态更新
  -> 删除已选数量更新
  -> Popconfirm 确认
  -> api.deleteRuns(选中的已结束 ID)
  -> 失效 runs/patrolRuns/reports 查询
  -> 列表、分页和选择状态刷新

用户删除当前范围
  -> Popconfirm 显示当前筛选范围和数量
  -> 分页收集当前筛选范围 ID
  -> api.deleteRuns(当前范围内已结束 ID)
  -> 列表、分页和选择状态刷新
```

## 技术决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 删除接口 | 复用现有批量删除接口 | 保持权限、关联数据清理和失败反馈行为一致 |
| 数量来源 | 服务端分页响应的 `deletable_count` | 跨页准确且排除运行中日志，不新增详情请求 |
| 删除全部范围 | 确认时按当前筛选条件收集 ID | 服务端分页下当前页不代表全部筛选结果，避免数量与实际删除不一致 |
| 布局策略 | 操作栏局部 flex 换行 | 改动小、兼容 Ant Design Card extra，不影响其他页面 |
| 未选择反馈 | 禁用按钮配合 Tooltip/辅助文案 | 防止误触，同时解释如何启用，不改变删除安全边界 |
| 测试方式 | 纯函数单测 + Playwright 页面回归 + 构建 | 覆盖数量逻辑、真实交互和窄窗口视觉布局 |
