# 巡检运行故障正常展示 Spec

## 背景

自动巡检可能因上游服务临时不可用、HTTP 5xx、网络连接失败或请求超时而无法取得有效探针结果。这类失败只说明本轮无法完成判断，不代表渠道存在身份泄漏、Signature 协议拒绝或其他真实性异常。当前任务列表仍会把它们显示为红色异常并要求复审，容易造成误报。

## 目标

- 将可识别的运行故障在任务列表中按正常状态展示，不触发异常或复审提示。
- 保留运行故障的原始证据，便于在详情中排查上游可用性。
- 继续突出真正的身份和协议异常。

## 功能需求

- F1: 当一次巡检仅包含 HTTP 5xx、网络连接失败、请求超时、上游临时不可用或额度不足等运行故障时，任务列表显示正常状态，不显示红色异常或需要复审。
- F2: 当身份探针或 Signature 探针因上述运行故障失败时，不显示对应的红色失败标记。
- F3: 运行故障的错误内容、请求标识和相关证据仍可在巡检详情中查看。
- F4: Kiro 身份泄漏和明确的 `Invalid signature in thinking block` HTTP 400 拒绝仍按异常展示并要求复审。
- F5: 当同一轮同时包含运行故障和真实异常时，以真实异常为准，继续显示异常和需要复审。

## 非功能需求

- N1: 展示判断与现有后端“运行故障不参与真伪判断”的口径保持一致。
- N2: 不删除或改写已记录的原始请求、响应、错误文本和标签。
- N3: 不影响普通任务列表、巡检执行、评分、告警发送和后端分类逻辑。
- N4: 兼容历史巡检结果中仅有 HTTP 状态或错误文本、缺少结构化运行故障标签的数据。

## 不做的事

- 不把所有请求失败都视为正常。
- 不忽略 Kiro 身份泄漏、明确的 Signature 400 拒绝或其他真实协议异常。
- 不新增自动重试、渠道禁用、额度补充或告警规则。
- 不修改后端已有运行故障分类。

## 验收标准

- AC1: HTTP 500、502、503、504、网络连接失败、超时、上游临时不可用和额度不足的单一故障结果，在任务列表显示正常且不显示需要复审。
- AC2: 身份探针或 Signature 探针因运行故障失败时，不出现对应的红色叉号；原始错误仍能在详情中查看。
- AC3: Kiro 身份泄漏和 HTTP 400 `Invalid signature in thinking block` 仍显示异常并要求复审。
- AC4: 运行故障与真实异常同时出现时，任务列表仍显示异常并要求复审。
- AC5: 前端单元测试、生产构建和差异格式检查通过，工作区其他未提交改动保持不变。
