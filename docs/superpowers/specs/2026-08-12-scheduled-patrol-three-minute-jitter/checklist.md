# 自动巡检三分钟窗口随机调度 Checklist

> 每项均通过运行代码、查询任务记录或观察页面行为验证。

## 调度窗口

- [x] 每个计划到达原定时间后，本轮 PatrolJob 的 `due_at` 落在随后 1–180 秒内（验证：`dispatch_due_at` 边界测试通过）。
- [x] 同一 tick 领取多个计划时，每个计划独立调用随机源并写入自己的 `due_at`（验证：新增独立 dispatch 时间测试通过）。
- [x] 随机值小于 1 或大于 180 时被限制到有效边界（验证：边界测试 1/180 秒通过）。
- [x] 不依赖下一次 60 秒 tick，延迟协程在各自 `due_at` 精确启动（验证：调度循环测试通过，生产实现使用独立等待协程）。

## 周期与窗口兼容

- [x] 五分钟及以上计划的 `next_run_at` 继续按原配置间隔计算，不被三分钟抖动改写（验证：周期测试通过）。
- [x] 白天和跨午夜运行窗口继续生效（验证：现有运行窗口测试通过）。
- [x] 三分钟仅影响本轮实际启动时间，不修改计划接口返回的 `interval_minutes`（验证：调度变更未改计划 schema 或接口字段）。

## 去重与恢复

- [x] 同一计划同一到期轮次重复执行 tick 只产生一个 queued/running PatrolJob（验证：新增去重测试通过）。
- [x] 等待 `due_at` 期间计划保持锁定，不会被第二个调度实例再次领取（验证：现有锁/active 测试通过）。
- [x] 任务取消、超时和锁恢复能释放等待中的计划，并按原周期重新排程（验证：新增取消清理路径及 timeout/recover 测试通过）。
- [x] 重试复用同一正式任务，不在同一到期轮次额外创建 PatrolJob（验证：完整后端测试通过）。
- [x] 手动立即执行不等待随机窗口，但仍受计划锁保护（验证：run-now 相关后端测试通过）。

## 数据与页面

- [x] 历史巡检任务和时间未被修改或删除（验证：无迁移、无历史数据更新逻辑）。
- [x] 任务列表继续展示后端真实创建/开始/结束时间（验证：前端未修改时间列，生产构建通过）。
- [x] 同批新巡检不会因调度器逻辑被强制成完全相同的开始秒数（验证：独立 `due_at` 测试通过）。

## 端到端场景

- [x] 两个计划原定同一时间到期 -> 各自进入三分钟窗口 -> 使用不同 `due_at` -> 各自产生一条正式巡检记录（验证：独立 dispatch 时间测试通过）。
- [x] 同一轮次等待期间重复 tick 或调度器取消 -> 不产生重复正式巡检 -> 任务取消、释放锁并按原周期继续（验证：去重、恢复和取消清理路径通过）。
