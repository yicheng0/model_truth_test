# 飞书仅播报 Signature 异常与检测任务列表移除 Spec

## 背景

当前飞书自动巡检小时消息除 Signature 异常外，还会展示巡检次数、正常数量、真实性异常数量、运营问题、渠道综合情况和 Kiro 身份泄漏等内容，产生与当前关注目标无关的通知噪音。

检测任务页面顶部还保留一整块普通检测任务列表，包含批量选择与删除、渠道分组、任务数、最近状态、最近进度、最近任务和最近创建时间。当前工作重点已经转为自动巡检及 Signature 异常，这部分功能不再需要展示。

## 目标

- 飞书自动巡检通知只统计并播报明确的 Thinking Signature 拒绝问题。
- 飞书正文只展示定位 Signature 异常所必需的安全证据，不再展示其他巡检统计或异常类型。
- 移除截图二所示的普通检测任务列表及其相关操作入口。
- 保留站内自动巡检日志、Signature 原始证据和必要的诊断能力。

## 功能需求

- F1: 只有 Relay 明确拒绝 Thinking Signature 的巡检结果，才允许触发飞书自动通知。
- F2: Kiro 身份泄漏、普通真实性异常、低评分、协议偏差、运营故障、正常巡检结果及其他非 Signature 情况，均不得触发飞书自动通知。
- F3: 飞书自动消息只展示 Signature 异常标题、发生时间、Source 渠道、Relay 渠道、固定错误摘要，以及双方可用的 Message ID 和 Request ID。
- F4: 飞书自动消息不得展示巡检总数、正常数、真实性异常总数、运营问题数、渠道综合情况、最低分、Kiro 异常或其他非 Signature 明细。
- F5: 没有明确 Signature 异常的统计时间窗不得发送“零异常”或普通运行情况消息。
- F6: 检测任务页面移除截图二对应的普通检测任务列表整块内容，包括批量选择、批量删除、渠道分组表、展开后的任务明细，以及任务数、状态、进度、最近任务和创建时间等展示。
- F7: 检测任务页面保留创建检测任务的入口，以及下方自动巡检日志、渠道筛选、异常筛选、Signature 异常提示、详情查看和巡检日志删除能力。
- F8: 非 Signature 结果仍可保留在站内报告、自动巡检日志和原始证据中，但不得计入 Signature 异常数量或飞书通知。

## 非功能需求

- N1: 飞书消息继续执行现有敏感信息脱敏，不发送完整 Signature、完整 thinking、API Key、认证头或未脱敏原始请求与响应。
- N2: Signature 异常继续沿用现有去重、发送重试和小时任务互斥机制。
- N3: 不新增数据库迁移、队列、任务类型或渠道配置。
- N4: Mock 模式、SQLite 本地开发和现有自动巡检执行流程保持可用。
- N5: 保留用户当前未提交的无关文档改动，不纳入本次修改。

## 不做的事

- 不删除数据库中的历史普通检测任务、报告或结果。
- 不删除后端普通检测任务接口，也不阻止通过现有创建入口发起检测；本次只移除截图二对应的列表展示与操作。
- 不删除站内 Kiro 身份泄漏记录或其他诊断证据，只停止其飞书自动播报。
- 不改变 Signature 的检测、Source/Relay 判定或原始证据展示规则。
- 不修改自动巡检周期、渠道启停、评分或真实性判断方法。
- 不修改飞书机器人配置测试消息；测试消息仍用于验证 Webhook 配置。
- 不在本次范围内修改飞书日报，除非日报复用了同一自动 Signature 通知正文且必须同步避免非 Signature 内容泄漏。

## 验收标准

- AC1: 同一小时同时出现明确 Signature 拒绝、Kiro 身份泄漏、普通真实性异常和运营问题时，飞书只收到 Signature 异常内容。
- AC2: 只有 Kiro、普通异常、运营问题或正常结果的小时，不产生自动飞书消息。
- AC3: 飞书 Signature 消息中能看到发生时间、Source、Relay、固定错误摘要和可用的双方标识，且看不到巡检统计、运营问题、渠道综合情况、最低分或 Kiro 内容。
- AC4: 飞书 Signature 消息不包含完整 Signature、完整 thinking、密钥、认证头或未脱敏原始请求与响应。
- AC5: 打开检测任务页面，看不到截图二中的普通检测任务批量选择、删除和渠道分组任务表。
- AC6: 检测任务页面仍能进入“提取渠道指纹”和“真实性对比”，并能正常查看与操作自动巡检日志。
- AC7: 站内仍可查看 Kiro、运营故障及其他非 Signature 的巡检记录和诊断证据，但它们不进入 Signature 数量和飞书发送状态。
- AC8: 飞书测试消息仍可正常发送；Signature 异常的去重、重试与小时互斥行为保持有效。
- AC9: 后端相关自动化测试、前端测试和生产构建通过，且本次改动不包含现有无关文档变更。
