## T1: 为分页和删除范围补充失败测试

**文件：** `frontend/src/runsUtils.test.ts`

**依赖：** 无

**步骤：**
1. 增加构造不同状态、不同渠道和不同顺序巡检日志的测试数据。
2. 编写分页切片测试：页码从 1 切换到 2 时返回第二页，改变每页条数时返回对应行集合，并保持输入顺序。
3. 编写页码校正测试：空列表返回第 1 页，超出总页数时返回最后有效页，合法页码保持不变。
4. 编写按渠道删除 ID 测试：全部渠道返回所有已结束 ID，具体渠道只返回该渠道已结束 ID，运行中/等待中日志不返回，其他渠道不受影响。

**验证：** 运行 `cd frontend && npx vitest run src/runsUtils.test.ts`，新增测试应先失败，原因是辅助函数尚未实现。

## T2: 实现纯函数分页和删除范围逻辑

**文件：** `frontend/src/runsUtils.ts`

**依赖：** T1

**步骤：**
1. 增加分页切片函数，使用安全的页码和每页条数计算起止位置，不修改输入数组。
2. 增加页码校正函数，将页码限制在 `1..maxPage`，空列表的最大页码固定为 1。
3. 增加按当前筛选集合计算可删除巡检日志 ID 的函数，只接受已结束状态，并保持原始顺序。
4. 保持现有导出和类型兼容，不改动已有渠道筛选、缓存清理和普通任务工具行为。

**验证：** 重跑 `cd frontend && npx vitest run src/runsUtils.test.ts`，新增和既有测试全部通过。

## T3: 接入自动巡检日志受控分页

**文件：** `frontend/src/pages/Runs.tsx`

**依赖：** T2

**步骤：**
1. 增加自动巡检日志当前页码和每页条数状态，默认页码为 1、每页 10 条。
2. 根据 `filteredPatrolRuns` 计算有效页码和当前页数据，表格 `dataSource` 改为当前页数据。
3. 将表格分页改为受控配置，处理页码切换和每页条数切换；每页条数变化时回到第一页。
4. 渠道筛选变化时重置页码；筛选结果或缓存刷新后使用页码校正逻辑，避免停留在空的无效页。
5. 保持展开行、行选择、详情、复审、取消和轮询刷新行为不变；行选择清理继续基于当前筛选集合。

**验证：** 运行 `cd frontend && npm run build`，TypeScript 构建成功；运行现有前端测试，确认页面相关工具测试无回归。

## T4: 将批量删除范围绑定当前渠道类别

**文件：** `frontend/src/pages/Runs.tsx`

**依赖：** T2、T3

**步骤：**
1. 将“删除全部已结束”候选集合从全部 `patrolRuns` 改为当前 `filteredPatrolRuns`，再过滤已结束日志。
2. 未筛选时确认文案显示全部类别和实际数量；选择具体渠道时显示渠道名称、实际数量，并明确只处理该渠道。
3. 确认文案继续说明仅删除已结束日志，以及结果、报告和关联告警会一并删除。
4. 删除成功后清理巡检行选中状态、更新 `runs` 缓存并失效 `runs`/`reports` 查询；保留失败项以便展示后端保护原因。
5. 确认删除按钮的禁用、加载、空状态和数量在筛选、删除、刷新后即时同步。

**验证：** 运行 `cd frontend && npx vitest run`，前端全量测试通过；必要时使用本地页面手动验证全部渠道和具体渠道两条删除路径。
