# 自动巡检日志分页与按类别删除 Spec

## 背景

自动巡检日志表格虽然展示分页控件，但当前页码和每页条数没有被页面状态明确管理，筛选、刷新或删除后容易出现页码显示变化但日志内容没有按预期切换的情况。用户还需要在选择某个渠道后，一次性删除该渠道的一类历史巡检日志，以便清理问题渠道的旧记录。

## 目标

- 修复自动巡检日志分页，使页码和每页条数真正控制可见日志。
- 在渠道筛选范围内提供按类别批量删除已结束日志的能力。
- 保留现有逐条查看、展开、复审、取消和删除已选行为。

## 功能需求

- F1: 自动巡检日志分页器的页码、上一页、下一页和每页条数都能真实改变表格中显示的日志；默认排序和日志总数保持不变。
- F2: 渠道筛选变化后，分页回到第一页；当前筛选结果减少或删除后，如果当前页超出可用页数，自动回到最后一个有效页。
- F3: 在未选择具体渠道时，用户可以触发“删除全部已结束巡检日志”，删除所有当前可删除的已结束自动巡检日志。
- F4: 选择一个渠道后，批量删除操作明确显示当前渠道名称和待删除数量，只删除该渠道中已结束且允许删除的日志，不影响其他渠道日志。
- F5: 批量删除完成后，表格、分页总数、选中状态和删除按钮数量立即刷新；运行中日志、基线引用阻断的日志继续保留并展示失败原因。
- F6: 删除确认文案明确说明删除范围、只处理已结束日志以及历史结果、报告和关联告警会一并删除。

## 非功能需求

- N1: 分页和批量删除使用当前已加载日志集合，不新增数据库字段；删除仍通过现有受保护的批量删除接口执行。
- N2: 分页状态、筛选状态和选中状态互相同步，不因 React Query 刷新造成重复删除或误选不可见行。
- N3: 不改变普通检测任务列表、渠道测试结果总览、日志详情和后端删除保护规则。
- N4: 批量操作保持现有权限校验、基线引用保护和敏感信息规则。

## 不做的事

- 不改造后端为服务端分页查询。
- 不增加跨页面的持久化筛选或新的删除权限角色。
- 不删除运行中的日志，也不绕过基线引用保护。
- 不同时修改普通检测任务和渠道总览的分页交互。

## 验收标准

- AC1: 在自动巡检日志超过一页时，切换第 2 页后表格显示第二页日志，切换每页条数后可见行数量和总页数同步变化。
- AC2: 切换渠道筛选后页码回到第 1 页；删除当前页或批量删除导致总页数减少时，页面不会停留在空的无效页。
- AC3: 未筛选时点击批量删除，确认框显示全部类别和实际数量，完成后所有可删除的已结束巡检日志消失，运行中/受保护日志保留。
- AC4: 选择某个渠道后点击批量删除，确认框显示该渠道名称和数量，完成后只删除该渠道日志，其他渠道日志和普通任务不变。
- AC5: 批量删除后分页总数、选中行、按钮状态和空状态即时正确；失败项显示后端返回的保护原因。
- AC6: 现有查看详情、展开证据、复审、取消运行、删除已选和轮询刷新行为不回归。
- AC7: 前端测试、TypeScript 构建和相关后端删除接口测试通过。
