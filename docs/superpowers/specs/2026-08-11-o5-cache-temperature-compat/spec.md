# o5 缓存测试 temperature 兼容修复 Spec

## 背景

缓存命中率测试当前会在预热请求和后续重复请求中携带固定采样温度。o5 模型已弃用该参数，因此测试会在缓存行为发生前返回 HTTP 400，错误信息为 ``temperature` is deprecated for this model`，导致无法获得缓存写入、缓存读取和命中率证据。

## 目标

- 让 o5 模型能够正常执行缓存预热和重复测试，不再因弃用的采样温度参数失败。
- 保持 Claude 及其他 Anthropic Messages 兼容渠道的缓存测试能力和统计口径不变。
- 保持原始请求证据可追踪，并能确认缓存探针没有发送无关的采样温度参数。

## 方案选择

- 推荐方案：缓存探针统一不发送采样温度。缓存测试只验证缓存控制和缓存 token，采样温度不是必要条件；该方案不依赖模型名识别，也不会制造额外失败请求。
- 备选方案一：仅在模型名识别为 o5 时移除采样温度。该方案可能因模型别名、代理改名或未来型号变化再次失效。
- 备选方案二：先按现状请求，命中弃用错误后移除参数重试。该方案会增加一次失败请求，并污染延迟、请求次数和成本证据。

## 功能需求

- F1: 缓存命中率测试的预热请求和所有重复请求不得携带采样温度参数。
- F2: 缓存命中率测试必须继续携带缓存控制信息、所选缓存有效期、独立探针标记和现有长文本样本。
- F3: 测试完成后必须继续记录缓存写入 token、缓存读取 token、请求命中率、Token 命中率、请求标识和协议端点等现有证据。
- F4: 该修复不得改变专门验证采样温度行为或 Thinking 与采样参数冲突的其他探针。

## 非功能需求

- N1: 保持 mock、本地 SQLite 和现有 Anthropic Messages 兼容渠道行为可用。
- N2: 不通过模型名称硬编码 o5 特例，避免模型别名和未来版本造成兼容漂移。
- N3: 不增加失败后重试，避免污染缓存测试的延迟、次数和成本证据。
- N4: 不持久化或展示 API Key、认证头及其他凭据。

## 不做的事

- 不调整缓存样本文本、缓存有效期、测试次数、等待间隔或命中率计算公式。
- 不修改通用模型请求页、Thinking temperature 冲突探针或测试套件中的参数一致性用例。
- 不新增模型能力注册表、自动降级重试或供应商专用路由。
- 不处理与本次 HTTP 400 无关的缓存不命中、渠道不支持缓存或 token 统计缺失问题。

## 验收标准

- AC1: 对缓存测试发起预热和至少一次重复请求时，记录的每一份原始请求证据均不包含采样温度参数。
- AC2: 使用会拒绝采样温度的 o5 兼容渠道执行缓存测试时，不再出现 ``temperature` is deprecated for this model` 的 HTTP 400，并能进入缓存结果统计流程。
- AC3: 5 分钟和 1 小时缓存有效期仍分别原样发送，独立探针标记及长文本样本保持存在。
- AC4: 现有缓存命中率测试覆盖通过，且专门测试 Thinking 与采样温度冲突的探针仍保留采样温度语义。
- AC5: 后端聚焦测试和完整回归测试通过，差异中不包含用户当前未提交前端工作的改写。
