# Signature 告警收紧与巡检随机秒间隔 Spec

## 背景

自动巡检发生网络错误、超时、服务端错误或资源不可用时，当前展示链路仍可能让用户看到 Signature 异常相关结论，容易把运营故障误解为 Thinking Signature 不兼容。

同时，短周期巡检目前按固定 5 分钟间隔触发，容易形成整分、整秒或可预测的请求时间。已观察到部分渠道在固定时间点与非固定时间点表现不同，因此短周期巡检需要改为 5 分钟以内的随机秒数间隔。

## 方案选择

- 方案 A（采用）：每轮结束后随机等待 1–300 秒再触发下一轮。时间不可预测，且满足 5 分钟以内随机秒数的要求。
- 方案 B：固定等待 5 分钟，再附加随机秒数。实际间隔会超过 5 分钟，不符合本次要求。
- 方案 C：仍按每 5 分钟一个时间窗口，只随机窗口内的执行秒数。相邻两轮间隔可能接近 0 秒或接近 10 分钟，行为不够稳定。

## 目标

- 只有上游明确拒绝 thinking block 中的 `signature` 时才报告 Signature 互通异常。
- 网络、超时、服务端、资源池、额度及其他非 Signature 错误只展示为运营或请求失败，不参与 Signature 异常判断。
- 将短周期自动巡检从固定 5 分钟改为每轮随机 1–300 秒间隔，避免整分整秒的规律请求。

## 功能需求

- F1: 只有错误内容明确表示 thinking block 的 `signature` 无效或被拒绝时，才产生 Signature 互通失败状态、异常标签和对应告警。
- F2: 网络错误、连接失败、超时、5xx、资源池无可用渠道、额度不足、身份请求失败、后处理失败及其他普通请求错误，不得产生 Signature 互通失败标签或 Signature 异常告警。
- F3: 非 Signature 请求失败应保留原始错误、错误阶段、HTTP 状态和请求标识，并按运营失败或无法判定展示，便于排查但不误导真伪判断。
- F4: 自动巡检的下一轮触发间隔每轮独立随机生成，范围为 1–300 个完整秒，包含 1 秒和 300 秒，不再固定为 300 秒。
- F5: 随机间隔应从当前轮完成、失败或超时后的调度基准重新计算；每次生成的实际下次运行时间可在巡检计划中查看。
- F6: 随机间隔不得绕过全局暂停、计划禁用、运行窗口、并发限制、调度锁和运行中任务保护。
- F7: 已产生的历史巡检证据不回写；新规则只作用于修改后新执行的巡检和新生成的告警。

## 非功能需求

- N1: Signature 判定在结果生成、报告汇总、告警生成和前端展示各层保持一致，任何一层都不得从普通网络错误重新推导 Signature 异常。
- N2: 随机秒数由后端生成并持久化为实际下次运行时间，服务重启后不得丢失或重新随机同一轮时间。
- N3: 随机生成应可在自动化测试中注入或固定，保证测试稳定、可重复。
- N4: 不记录或暴露 API Key、鉴权头及其他凭据；错误内容继续使用现有脱敏规则。
- N5: 保留 SQLite 和 PostgreSQL 兼容，不增加队列、Redis 或新的调度服务。

## 不做的事

- 不把仅包含普通单词 `signature`、但没有明确表示 thinking block signature 无效的模糊错误判为 Signature 异常。
- 不把 source 缺少 thinking block、缺少 signature 字段或未完成请求直接判为 Signature 不兼容；这些情况保持无法判定或证据缺失。
- 不修改失败重试间隔、每小时汇总等待时间和每日汇总时间。
- 不回溯修改历史报告、历史告警或历史运行记录。
- 不改变手动 Signature 互通测试的请求协议、模型选择和证据字段。

## 验收标准

- AC1: 使用明确包含 `Invalid signature in thinking block` 或 `Invalid \`signature\` in \`thinking\` block` 的上游错误执行测试，结果包含 Signature 互通失败标签并可生成 Signature 异常告警。
- AC2: 分别使用网络错误、连接超时、502/503、资源池无可用渠道、额度不足和普通 400 错误执行测试，结果均不包含 Signature 互通失败标签，也不生成 Signature 异常告警。
- AC3: AC2 中的错误仍能在巡检日志或详情中看到正确的运营失败分类、错误阶段、HTTP 状态、原始脱敏错误和请求标识。
- AC4: 连续计算多轮短周期巡检时间时，每轮间隔都在 1–300 秒范围内，并且测试可证明不再恒定为 300 秒。
- AC5: 巡检成功、请求失败和任务超时三种结束路径都会生成合法的随机下次运行时间；服务读取已保存的时间时不会再次随机。
- AC6: 计划暂停、禁用、运行窗口外、并发已满或调度锁占用时不会因随机间隔而提前执行或重复执行。
- AC7: Signature 相关后端测试、调度相关后端测试、前端测试和前端构建通过，现有手动测试、普通自动巡检、告警汇总和报告查看行为不回归。
