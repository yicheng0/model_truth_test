# 任务列表 Kiro 身份泄漏统计 Spec

## 背景

Claude 渠道的身份探针可能返回“你好，xxx，我是 Kiro”或 “I am Kiro” 等自报内容。这表明候选渠道可能混入 Kiro 路由或存在逆向代理身份泄漏，属于需要快速复审的高风险异常。后端对新结果已生成 `kiro_identity_leak` 结构化标签，但任务列表尚未在顶部异常汇总中统计和展示。

## 目标

- 在任务列表的任务展开区域顶部统计并展示 Kiro 身份泄漏。
- 与现有 Thinking Signature 400 异常放在同一异常汇总区域，便于集中复审。
- 没有明确 Kiro 身份泄漏证据时不显示该项。

## 功能需求

- F1: 当任务结果包含 `kiro_identity_leak` 标签时，异常汇总显示“Kiro 身份泄漏”及命中次数。
- F2: 为兼容历史结果，当身份探针响应正文明确自报“我是 Kiro”或 “I am Kiro”时，即使缺少结构化标签，也计入 Kiro 身份泄漏。
- F3: 汇总展示可用的 Request ID；多个匹配结果的 Request ID 去重并保持结果顺序。
- F4: Kiro 身份泄漏和 Thinking Signature 400 错误可以同时展示并分别统计。
- F5: 未命中时不显示 Kiro 提示，不改变任务状态、评分、进度、操作和详情链接。

## 非功能需求

- N1: 结构化 `kiro_identity_leak` 标签优先于文本判断。
- N2: 历史文本兼容只识别明确身份自报语境，不因渠道名称、配置、错误说明或普通讨论中出现 `kiro` 而误报。
- N3: 复用现有任务结果接口和脱敏数据，不展示 API Key、请求头或完整敏感响应。

## 不做的事

- 不修改后端现有 Kiro 标签生成、评分和巡检告警规则。
- 不把所有包含 `kiro` 的文本都判定为身份泄漏。
- 不把 Kiro 身份泄漏与 Thinking Signature 错误合并为同一种异常。
- 不新增自动重试、自动删除或自动禁用渠道行为。

## 验收标准

- AC1: 结果带 `kiro_identity_leak` 标签时，任务展开区顶部显示 Kiro 身份泄漏、命中次数和可用 Request ID。
- AC2: 历史身份响应明确包含“我是 Kiro”或 “I am Kiro”且无标签时，同样显示该异常。
- AC3: 渠道名称、配置或普通讨论文本仅包含 `kiro` 时，不显示身份泄漏。
- AC4: 多条命中结果去重 Request ID；与 Signature 400 同时命中时，两类异常均可见且分别统计。
- AC5: 完整前端测试、生产构建和差异格式检查通过，用户其他未提交前端工作不被改写。
