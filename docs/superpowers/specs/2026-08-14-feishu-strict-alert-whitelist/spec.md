# 飞书即时告警严格白名单 Spec

## 背景

自动巡检当前会依据评分、等级、异常标签和探针失败创建告警，并可能发送到飞书。普通协议偏差、低评分、运营故障或其他需要站内复核的异常，也可能进入飞书，造成告警噪音。

实际需要立即通知的只有两类证据明确的高优先级异常：上游明确拒绝 Thinking Signature，以及身份探针明确泄漏 Kiro。其他情况可以继续保留在站内报告、任务详情和统计汇总中，但不应作为飞书即时异常发送。

## 目标

- 飞书即时异常通知只发送明确 Thinking Signature 拒绝和 Kiro 身份泄漏。
- 截图中的 HTTP 400 `Invalid signature in thinking block` 必须发送飞书告警。
- 运营故障、普通探针异常、低评分及其他真实性标签不发送飞书即时告警。
- 保留站内报告、原始证据和现有人工复核能力。

## 功能需求

- F1: 当 Relay 返回明确的 `Invalid signature in thinking block` 错误时，系统发送飞书即时异常通知。
- F2: 当身份探针明确命中 Kiro 身份泄漏时，系统发送飞书即时异常通知。
- F3: 除 F1、F2 外，任何标签、评分、等级、失败状态或错误信息均不得触发飞书即时异常通知。
- F4: Signature 飞书告警必须依据明确错误正文进行确认，不能只依据 `signature_interop_failed` 历史标签、HTTP 400、失败状态或低评分发送。
- F5: Kiro 飞书告警优先使用结构化身份泄漏证据；普通身份不明确、身份请求失败或其他模型自报异常不发送。
- F6: 不满足即时告警白名单的站内告警和报告仍可保存，通知状态应明确表示未发送，而不是发送失败。
- F7: Signature 飞书即时通知必须明确包含待测 Source 渠道、验证 Relay 渠道、异常发生时间，以及 Source、Relay 两侧可用的 Message ID 和 Request ID；缺失的标识明确显示为未提供。
- F8: Kiro 飞书即时通知必须明确包含命中身份泄漏的待测渠道、异常发生时间，以及身份探针可用的 Message ID 和 Request ID。
- F9: 飞书即时通知应展示精简的明确错误摘要，例如 `Invalid signature in thinking block`，但不得发送完整 Signature、完整 thinking 内容、密钥、认证头或未脱敏原始请求与响应。
- F10: 小时汇总和日报继续作为运营与巡检统计存在，但运营问题不得表述成 Signature 或 Kiro 即时真实性告警。

## 非功能需求

- N1: 同一异常的静默期、去重和重试机制保持现状。
- N2: 不新增数据库迁移、队列、渠道配置或巡检任务类型。
- N3: 白名单判定必须在实际发送前再次执行，避免历史残留标签或旧告警被手动重发到飞书。
- N4: 现有飞书测试消息功能不受影响。

## 不做的事

- 不删除普通异常的站内记录、报告或详情证据。
- 不改变 Signature 和 Kiro 的检测方法及真实性结论。
- 不修改巡检评分、等级、执行周期或渠道状态。
- 不把网络、超时、HTTP 5xx、权限、额度、无可用渠道或账号等运营故障发送为即时异常。
- 不自动重发此前被新规则拦截的历史通知。

## 验收标准

- AC1: Relay 返回 HTTP 400 且正文明确包含 `Invalid signature in thinking block` 时，飞书收到一条 Signature 即时异常通知。
- AC2: 身份探针明确返回 Kiro 身份并形成 Kiro 泄漏证据时，飞书收到一条 Kiro 即时异常通知。
- AC3: `protocol_mismatch`、普通身份异常、低评分、D/E 等级、普通探针失败或其他非白名单标签均不发送飞书即时通知。
- AC4: 网络、超时、HTTP 5xx、权限、额度、无可用渠道或账号等运营故障不发送飞书即时通知。
- AC5: 历史告警仅带 `signature_interop_failed` 标签，但缺少明确 Signature 拒绝正文时，首次发送和手动重发都被跳过。
- AC6: 被跳过的告警在站内仍可查看，通知状态显示为未发送，并说明不符合飞书即时告警白名单。
- AC7: 真正的 Signature 或 Kiro 通知仍遵守现有去重、静默期和失败重试规则。
- AC8: 飞书测试消息仍可正常发送；小时汇总和日报仍可生成，且不会把运营问题描述成两类即时异常。
- AC9: Signature 告警中可以直接看到 Source 渠道、Relay 渠道、发生时间、错误摘要，以及两侧可用的 Message ID 和 Request ID；任一标识缺失时显示“未提供”。
- AC10: Kiro 告警中可以直接看到命中的待测渠道、发生时间、身份探针 Message ID 和 Request ID。
- AC11: 飞书通知正文不包含完整 Signature 值、完整 thinking 内容、API Key、认证头或完整原始请求与响应。
