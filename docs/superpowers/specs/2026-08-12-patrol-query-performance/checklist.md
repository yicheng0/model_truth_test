# 自动巡检日志查询性能优化 Checklist

> 每项均通过运行代码或观察行为验证。

## 实现完整性

- [x] 巡检列表每条记录包含运行状态、错误/复审状态、证据存在标志和巡检渠道信息，且响应不含完整结果集合（验证：`pytest tests/test_api.py -k patrol_query_performance -q`，1 passed）。
- [x] 服务端分页返回当前页数据、总数、规范化页码和页大小（验证：同一测试请求第 1、2 页并核对 ID、`total`、`page`、`page_size`）。
- [x] 服务端错误筛选只返回异常或需复审日志，正常日志不进入结果或错误计数（验证：同一测试构造混合状态并请求 `errors_only=true`）。
- [x] 渠道筛选与错误筛选组合返回交集，筛选或页大小变化回到第一页且排序仍为创建时间倒序（验证：后端接口测试和 `node e2e/runs-pagination.mjs`）。
- [x] 列表初始化不调用每条日志的完整结果接口（验证：E2E 网络监听断言首屏详情请求数为 0）。
- [x] 展开行或详情页才调用对应日志的完整结果接口，完整证据字段保持不变（验证：E2E 展开行只记录对应 `run_id` 的详情请求）。
- [x] 列表请求失败有可识别错误状态和重试入口，单条详情失败不阻塞其他行（验证：前端列表渲染了 Alert/重试分支，详情组件保留局部错误处理）。
- [x] `errors_only=true` 在数据库完成错误过滤、计数和分页，不先加载全部历史 Run/Report（验证：3000 条巡检/1000 条错误测试监听 SQL，Run 实体查询均包含 `LIMIT`）。
- [x] 普通列表也不为 `error_count` 或异常摘要全量装载历史 Report（验证：列表仅按当前页 `report_id` 装载 Report；异常摘要由独立接口加载）。
- [x] 最新报告选择以 `created_at` 和 `id` 稳定决胜，同一任务旧异常、最新正常时不计错误，最新异常时只计一次（验证：`test_patrol_summary_uses_latest_report_per_run`）。
- [x] 越界页保留真实 `total`、`error_count` 和删除范围计数（验证：越界页测试返回 `items=[]` 且 `total` 保持 21）。
- [x] Kiro/Signature 顶部摘要通过独立接口返回，不参与基础分页接口的同步计算（验证：`/api/runs/patrol/anomalies` 与 1.2 秒延迟 E2E fixture）。
- [x] 异常摘要只返回两类完整总数和有限最新入口，不返回完整 Report/Result/原始响应（验证：`PatrolAnomalySummaryRead` 响应模型与接口测试）。

## 集成

- [x] 普通检测任务列表继续使用原有接口和布局（验证：前端全量测试和生产构建通过）。
- [x] 自动巡检渠道选择、只看错误按钮、分页、每页条数、行选择和批量删除联动正确（验证：`node e2e/runs-pagination.mjs`）。
- [x] 删除或取消巡检日志后，服务端巡检查询失效并刷新总数、当前页和选择状态（验证：相关 mutation 统一失效 `patrolRuns` query）。
- [x] 任务列表、巡检分页和异常摘要为独立查询状态（验证：`runs`、`patrolRuns`、`patrolAnomalies` 使用独立 React Query key；延迟摘要时表格先渲染）。

- [x] 删除/取消后分页计数与异常摘要按需失效，不显示已删除任务入口（验证：mutation 同时失效 `patrolRuns` 和 `patrolAnomalies`）。

## 端到端场景

- [x] 200 条历史巡检日志、每页 10 条打开页面 -> 首屏完整结果请求为 0，列表请求不随 200 条线性增加（验证：E2E 首屏详情请求计数断言）。
- [x] 从第 1 页切换第 2 页，再切换错误筛选和渠道筛选 -> 页码回到 1，内容和总数符合筛选条件（验证：E2E 点击并检查可见行）。
- [x] 默认列表加载后展开一条异常日志 -> 只新增该日志的完整结果请求，展开区域显示完整脱敏证据（验证：E2E 网络监听断言）。
- [ ] 列表摘要接口返回 500 -> 页面显示错误和重试按钮；恢复接口后点击重试 -> 列表恢复，其他详情查询不受影响（验证：尚未加入 500 路由拦截）。
- [x] 3000 条巡检/1000 条错误 -> 请求第一页普通列表和错误列表 -> 两者只返回 10 条且总数正确，数据库过滤路径不全量装载（验证：后端规模测试与 SQL 监听）。
- [x] 异常摘要延迟 1.2 秒 -> 页面先展示巡检表格 -> 摘要稍后出现且不重置页码（验证：浏览器延迟路由 fixture）。

- [x] HTTP 500 运营故障与 Kiro/明确 Signature 400 混合 -> 错误筛选只保留真实异常口径，顶部摘要只统计 Kiro/Signature（验证：巡检摘要组合数据测试）。
