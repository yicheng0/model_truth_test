# 无品牌 JSON 身份填空探针 Spec

## 背景

当前自动巡检主要通过开放式身份询问识别身份泄漏。部分带额外人格或隐藏上下文的渠道会拒绝开放式身份问题，却可能在结构化填空中输出隐藏的品牌、产品或模型信息，因此现有单一身份问法可能漏检。

本次增加一条独立的无品牌 JSON 身份填空探针。探针请求不得出现任何厂商、产品或模型品牌名，以便区分“模型复述用户问题”和“响应主动泄漏未在请求中出现的身份信息”。

## 目标

- 在自动巡检中增加一条独立、结构化、无品牌污染的身份探针。
- 识别响应主动给出的 Kiro 或其他非预期身份信息。
- 保留完整且脱敏的请求、响应和上游标识，支持人工复核。
- 避免把拒答、空字段、格式错误、网络问题或一次普通幻觉直接判成模型替换。

## 功能需求

- F1: 每次自动巡检除现有探针外，额外执行一次 JSON 身份填空探针；该探针使用全新对话，不携带历史消息，不主动发送 system 内容，并且用户问题中不出现任何厂商、产品或模型品牌名。

- F2: 探针要求响应只包含 `vendor`、`product`、`model` 三个字符串字段；无法确认的信息允许留空。判定时允许从响应开头或单个 Markdown 代码块中提取一个合法 JSON 对象，以覆盖“JSON 后附带解释文字”的真实泄漏场景；额外文字必须单独记录为格式偏差。

- F3: 系统在请求发送前检查本次实际可见的探针文本，记录其未包含受监控品牌词；如果请求被品牌词污染，则该次结果只能标记为无效证据，不得用于身份异常结论。

- F4: 当有效响应的 `vendor`、`product` 或 `model` 字段主动出现 Kiro 时，记录 `hidden_brand_leak` 和 `kiro_identity_leak`，并将该探针标记为身份异常。

- F5: 当有效响应主动出现明确的其他非 Claude/Anthropic 身份时，记录 `hidden_brand_leak` 和 `identity_mismatch`，但不自动记录 Kiro 标签。

- F6: 当提取出的合法对象填写 Claude 或 Anthropic、字段为空或明确表示无法确认时，不记录 `hidden_brand_leak`。纯拒答、完全找不到合法 JSON 对象或对象结构不完整时也不记录 `hidden_brand_leak`。系统分别保留正常、身份待确认、拒答、额外文字或格式异常状态，供人工复核；如果合法对象已经命中品牌，后续解释文字不得抹掉该泄漏证据。

- F7: HTTP 失败、超时、权限、额度或上游资源不可用继续归为运营问题，不得记录身份泄漏或模型替换。

- F8: 探针结果应作为独立证据项展示，至少保留探针名称、状态、解析后的字段、命中的标签、Message ID、Request ID、HTTP 状态、发生时间及脱敏后的原始响应。

- F9: 新探针可以影响站内自动巡检风险结论和异常日志，但不得进入飞书即时通知；飞书仍只发送明确的 Thinking Signature 拒绝。

- F10: 新探针不替换现有开放式身份探针。两者结果分开保存，最终报告应能区分“直接身份自报异常”和“无品牌结构化探针泄漏”。

## 非功能需求

- N1: API Key、认证头和其他凭据不得进入数据库、报告、日志或页面。
- N2: Mock 模式下结果必须稳定、可重复，并覆盖正常、Kiro 泄漏、拒答、格式错误和运营失败。
- N3: 不增加额外重试轮次；每次自动巡检只增加一次模型请求，避免巡检成本失控。
- N4: 不改变现有 Signature、thinking、Web Search、参数兼容性和普通任务执行逻辑。
- N5: 对响应字段的匹配忽略大小写和常见空白差异；只读取合法对象中的三个指定字段，不从后续解释文字、其他字段或请求之外猜测和补全身份。

## 不做的事

- 不加入续写陷阱、翻译绕过、字符计数或 CLEAN/DIRTY 等其他新探针。
- 不在本次实现三轮重复采样或官方基线差分。
- 不通过 token usage 差异判断是否存在隐藏 system 内容。
- 不仅凭单条 JSON 探针就断言底层模型一定被替换。
- 不修改飞书 Signature-only 白名单。
- 不新增数据库迁移、队列、身份系统或凭据持久化。

## 验收标准

- AC1: 查看实际发送的探针请求时，用户文本不包含 Kiro、Claude、Anthropic、OpenAI 等受监控身份品牌，且没有用户侧 system 内容或历史消息。

- AC2: 响应 `{"vendor":"Kiro","product":"Kiro","model":""}`，或先返回该合法 JSON 再附带解释文字时，站内证据均记录 `hidden_brand_leak` 和 `kiro_identity_leak`，并保存安全定位信息；后者同时记录输出格式偏差。

- AC3: 响应明确填写其他非 Claude/Anthropic 身份时，记录 `hidden_brand_leak` 和 `identity_mismatch`，但不记录 `kiro_identity_leak`。

- AC4: 合法对象填写 Claude/Anthropic或全部留空时不记录 `hidden_brand_leak`；纯拒答、完全无法提取合法对象或对象缺少指定字段时也不记录，并显示对应的正常、待确认、拒答、额外文字或格式异常状态。

- AC5: 探针发生 HTTP 失败、超时、权限、额度或资源不可用时，只记录运营状态，不生成身份异常。

- AC6: 自动巡检报告和日志可分别查看现有开放式身份探针与新增 JSON 探针的结果、标签和上游标识。

- AC7: 新探针命中 Kiro 后可进入站内异常汇总，但执行飞书小时任务时不会调用 Webhook，除非同一小时另有符合条件的明确 Thinking Signature 拒绝。

- AC8: Mock 自动巡检、后端完整测试、前端完整测试和生产构建均通过，现有 Signature 与其他巡检探针无回归。
