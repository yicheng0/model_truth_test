# 自动巡检重启锁恢复 Checklist

> 每项均通过运行代码或观察行为验证。

## 实现完整性

- [x] 旧实例持有、锁尚未到期的 queued/running 计划在新进程启动恢复时被识别并释放（验证：测试数据库构造未来锁并运行恢复流程，期望计划锁清空且 `next_run_at` 可重新派发）。
- [x] 被部署中断计划关联的 queued/running 作业和 running 尝试被结束（验证：查询关联 `PatrolJob` 与 `PatrolJobAttempt`，期望不再处于 queued/running，并包含部署重启中断原因）。
- [x] 被部署中断计划关联的 pending/running 运行记录被结束为 `interrupted`（验证：查询关联 `Run`，期望状态为 `interrupted` 且有结束时间和中断说明）。
- [x] 当前实例正在执行的计划及关联记录不被恢复流程修改（验证：构造当前实例锁，比较恢复前后所有状态、锁和时间字段）。
- [x] 恢复流程重复执行保持幂等（验证：连续调用两次并比较状态、时间和记录数量，期望第二次无新增变更）。
- [x] 恢复异常被脱敏记录且不会终止调度循环（验证：注入一次数据库恢复异常，期望日志无凭据、心跳继续更新，后续检查可成功恢复）。

## 集成

- [x] 应用启动顺序先完成数据库初始化和旧实例恢复，再启动监督调度循环（验证：启动日志与生命周期测试，期望恢复调用发生在 scheduler task 创建前）。
- [x] 每轮调度在续租当前实例活跃锁后执行旧实例兜底恢复，再进行到期计划派发（验证：tick 测试，期望当前实例锁保持、旧实例锁释放并产生可派发计划）。
- [x] 健康接口不再统计已恢复的遗留排队/运行/逾期任务（验证：调用健康接口，期望 `running_schedule_count`、`overdue_schedule_count` 和 `overdue_job_count` 不包含已中断记录）。

## 编译与测试

- [x] 后端调度恢复和接口测试通过（验证：`cd backend && python -m pytest backend/tests/test_api.py -k "scheduled or patrol"`，期望退出码为 0）。
- [x] 后端完整测试通过（验证：`cd backend && python -m pytest`，期望退出码为 0；既有基线失败单独记录）。
- [x] 后端 Python 模块编译通过（验证：`cd backend && python3 -m compileall -q app`，期望退出码为 0）。
- [ ] 生产部署构建通过（验证：按项目现有 Docker Compose 部署命令构建 backend，期望服务健康且无启动异常）。

## 端到端场景

- [ ] 部署重启中断 -> 自动恢复 -> 新巡检派发（验证：重启生产 backend，查看启动日志、健康接口和下一轮运行记录，期望无需人工 SQL 清锁即可产生新任务）。
- [ ] 当前实例正常任务 -> 重启恢复检查（验证：在测试中保留当前实例活跃任务，触发恢复检查，期望任务继续执行且锁被续租）。
- [ ] 恢复失败 -> 调度继续心跳 -> 后续恢复成功（验证：第一次恢复故障后观察健康心跳，再解除故障并等待下一 tick，期望遗留计划最终恢复且调度不中止）。
- [ ] 多次恢复和已完成历史记录边界（验证：重复运行恢复检查并包含已完成计划/运行记录，期望已完成历史不被修改、不重复生成作业）。
