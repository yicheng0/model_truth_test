# 自动巡检日志错误筛选 Spec

## 背景

当前自动巡检日志表格需要增加一个图 2 所示的错误筛选入口，按需查看异常日志。用户只需要快速筛出错误记录，不需要新增复杂的错误详情展示。

自动巡检日志已经具备结果状态、复审状态、渠道筛选、分页和批量删除能力。本需求只调整错误日志的筛选交互，不改变已有巡检证据、详情页和异常分类规则。

## 目标

- 在“自动巡检日志”卡片顶部的工具区域增加“只看错误”按钮。
- 默认展示全部日志；按钮关闭时不改变现有列表展示。
- 开启按钮后，只显示当前结果状态为异常或需要复审的日志；显示“正确”的日志不进入结果，也不计入错误数量。
- 按钮筛选与现有渠道筛选、分页、每页条数、行选择和批量删除联动。

## 功能需求

- F1: 自动巡检日志工具栏提供“只看错误”按钮，默认关闭。
- F2: 按钮开启后只保留现有结果状态为异常或需要复审的日志；结果状态为正确的日志完全排除。
- F3: 错误按钮与渠道筛选同时生效，列表只保留同时满足两个条件的日志。
- F4: 错误筛选结果驱动分页总数、当前页和每页条数；切换按钮、渠道或页大小时回到第一页。
- F5: 行选择、删除已选和删除当前筛选范围只作用于当前可见错误日志；隐藏的正确日志不得被误删。
- F6: 按钮关闭时保持现有巡检结果、复审、展开和详情操作，不新增默认错误正文。

## 非功能需求

- N1: 复用现有前端巡检结果状态和异常分类规则，不新增后端接口、数据库字段或持久化错误副本。
- N2: 筛选只使用已脱敏的证据字段；不在列表、筛选标签或计数中展示 API Key、鉴权头、完整签名或其他凭据。
- N3: 控件放在现有自动巡检日志卡片工具栏，与渠道选择和删除操作保持一致的紧凑布局，不新增独立页面。
- N4: 正常状态的列表排序保持不变；筛选只改变集合，不改变集合内部顺序。
- N5: 保留当前工作区中与本需求无关的 Claude Code 未提交修改，不扩大暂存和提交范围。

## 不做的事

- 不新增后端错误查询接口、服务端分页或数据库迁移。
- 不修改后端巡检评分、告警生成、运营故障与真实性异常的分类边界。
- 不把所有失败任务都视为错误日志；按钮只复用现有“异常/需要复审”结果状态。
- 不新增错误正文、原始请求/响应或独立错误统计模块。
- 不修改普通检测任务列表、渠道总览和巡检详情页的既有布局。

## 验收标准

- AC1: 打开自动巡检日志时显示“只看错误”按钮且默认关闭；点击后按钮进入开启状态。
- AC2: 构造正确、异常和需要复审日志；开启按钮后只显示异常/需要复审日志，正确日志不显示也不计数。
- AC3: 同时选择渠道 A 和“只看错误”时，只显示渠道 A 中的异常/需要复审日志；关闭按钮后恢复该渠道全部记录且顺序不变。
- AC4: 错误筛选结果分页、页大小和筛选切换行为正确；切换筛选或页大小后回到第一页。
- AC5: 错误筛选状态下删除只作用于当前可见错误日志，正确日志和运行中日志保留。
- AC6: 按钮关闭时原有结果、复审、展开和详情操作无回归。
- AC7: 前端单元测试、生产构建和浏览器交互测试通过。
