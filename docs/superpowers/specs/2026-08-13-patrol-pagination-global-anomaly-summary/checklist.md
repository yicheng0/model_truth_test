# 自动巡检分页与全局异常置顶 Checklist

> 每项均通过运行代码或观察行为验证。

## 分页实现完整性

- [x] 点击第 6 页后，分页器选中页、分页请求参数和表格记录均为第 6 页（验证：准备至少 65 条日志，点击数字 6，观察请求包含 `page=6&page_size=10`、第 6 页处于选中状态且表格出现第 51-60 条记录）。
- [x] 第 6 页查询完成后不会自动跳回第 1 页（验证：等待目标页响应完成，继续等待一次轮询间隔，期望分页器和表格仍停在第 6 页）。
- [x] 旧第 1 页响应不会覆盖用户新选择的第 6 页（验证：让第 1 页响应延迟至点击第 6 页后返回，期望第 6 页选中状态和记录保持不变）。
- [x] 上一页和下一页与实际请求和内容一致（验证：从第 6 页点击上一页看到第 5 页记录，再点击下一页恢复第 6 页记录；每次请求页码与选中页一致）。
- [ ] 首尾页跳转与实际请求和内容一致（验证：从第 6 页点击第 1 页和末页，期望分别展示第 1 页和最后一页记录，不出现中间页残留）。
- [ ] 有效后页不会因短暂空数据重置为 1（验证：查询切换期间暂时无新数据，期望分页器保持目标页，加载完成后显示目标页记录）。
- [ ] 请求真实越界页时保留总数并校正到最后有效页（验证：删除数据使当前页超过总页数，期望接口仍返回真实总数，页面自动请求并显示最后有效页）。
- [ ] 真实空范围才回到第 1 页（验证：切换到无任何日志的渠道，期望总数为 0、当前页为 1、页面显示空状态）。
- [ ] 切换渠道后显式回到第 1 页（验证：在第 6 页切换渠道，期望下一次请求为该渠道 `page=1`，表格内容只属于该渠道）。
- [ ] 更改每页条数后显式回到第 1 页（验证：在第 6 页从 10 条/页切到 20 条/页，期望请求 `page=1&page_size=20`，分页和表格数量同步变化）。
- [ ] 切换“只看错误”后分页和过滤范围一致（验证：在后页切换开关，期望回到第 1 页并只显示真实错误，关闭后恢复普通日志范围）。

## 全局异常摘要

- [x] Kiro 摘要统计当前渠道下全部分页命中（验证：在第 1 页之外放置多个 Kiro 记录，停留第 1 页时顶部显示跨页总数）。
- [x] Signature 摘要统计当前渠道下全部分页命中（验证：在不同分页放置 HTTP 400 明确 Signature 拒绝，停留任意页时顶部显示跨页总数）。
- [x] Kiro 与 Signature 两类异常分开显示（验证：两类同时命中，期望出现两个独立提示、各自数量和入口，不能合并成普通错误总数）。
- [ ] 无 Kiro 命中时不显示 Kiro 提示（验证：切换到无 Kiro 的渠道，期望 Kiro Alert 完全消失，不保留空白占位）。
- [ ] 无 Signature 命中时不显示 Signature 提示（验证：切换到无明确拒绝的渠道，期望 Signature Alert 完全消失）。
- [x] 渠道筛选同步约束摘要范围（验证：全部渠道显示全局数量，切换单一渠道后数量和入口只保留该渠道记录）。
- [x] “只看错误”不改变顶部真实性异常统计（验证：同一渠道开启和关闭“只看错误”，期望两类异常总数和入口保持一致，只有表格范围变化）。
- [ ] 摘要入口使用每个任务最新报告（验证：同一任务写入旧异常报告和更新后的正常报告，期望不重复统计旧异常；反向写入最新异常则只统计一次）。
- [ ] 摘要入口按最新时间稳定排序（验证：创建多个命中任务，期望入口顺序从新到旧，多次请求顺序一致）。
- [ ] 摘要入口数量受限但总数完整（验证：创建超过入口上限的异常，期望 `count` 为全部命中数、入口为固定上限，并显示剩余数量）。
- [ ] 点击 Kiro 入口进入对应巡检详情（验证：点击任务链接，期望路由为 `/runs/{run_id}`，详情可查看身份探针 Request ID、阶段和脱敏证据）。
- [ ] 点击 Signature 入口进入对应巡检详情（验证：点击任务链接，期望详情可查看 HTTP 400、Relay/Signature 阶段、Request ID 和明确拒绝错误）。

## 误报与安全边界

- [x] `signature_ok=null` 不计入 Signature 摘要（验证：构造未知三态记录，期望 Signature 数量不增加）。
- [x] 权限禁止和账号/模型无权不计入 Signature 摘要（验证：构造 `access forbidden` 与 `models is not allowed for this account`，期望顶部数量不增加）。
- [x] 配额、网络、超时、HTTP 5xx 和临时不可用不计入两类摘要（验证：逐类构造运营故障，期望 Kiro/Signature 数量均不增加）。
- [x] 普通 HTTP 400 不计入 Signature 摘要（验证：状态为 400 但错误文本不匹配明确拒绝，期望不显示或不增加 Signature 数量）。
- [ ] 普通文本讨论 Signature 不计入摘要（验证：响应正文只解释 Signature 概念，期望不命中）。
- [ ] 普通文本出现 Kiro 名称不计入身份泄漏（验证：渠道配置、问题文本或否定句包含 Kiro，但没有明确身份自报，期望不命中）。
- [x] 历史明确 Kiro 身份自报可命中（验证：缺少结构化标签但身份响应明确包含“我是 Kiro”或“I am Kiro”，期望 Kiro 数量增加）。
- [x] 历史明确 Signature 拒绝可命中（验证：缺少新结构化字段但 HTTP 400 且错误精确匹配，期望 Signature 数量增加）。
- [ ] 顶部不展示 API Key、鉴权头、完整 Thinking Signature 或完整原始响应（验证：检查页面文本和接口摘要，仅存在脱敏任务、渠道、Request ID、状态和阶段）。

## 查询与集成

- [ ] 首页只发起固定数量的轻量查询（验证：记录网络请求，期望巡检分页和现有固定页面请求，不按日志数量逐条调用 `/api/runs/{id}/results`）。
- [ ] 切换页码不触发全部日志详情请求（验证：连续切换第 1、6、末页，期望完整结果请求数保持为 0，除非用户主动展开或点击详情）。
- [ ] 异常摘要响应不包含完整 Result、Report 或原始证据集合（验证：检查 `/api/runs/patrol` 响应结构，仅包含轻量分页条目和有限异常入口）。
- [ ] 错误筛选计数与异常摘要口径互不覆盖（验证：运营错误仍按已批准列表口径显示为正常或运营状态，顶部只统计 Kiro/明确 Signature）。
- [ ] 删除当前范围仍覆盖全部过滤分页（验证：删除范围操作继续收集所有可删除任务，顶部摘要和分页修复不把范围缩成当前页）。
- [ ] 未结束任务仍不能被删除（验证：pending/running 日志保持禁用或被后端拒绝，分页和异常改动不绕过保护）。
- [ ] 普通检测任务列表不受影响（验证：普通任务表的加载、分页/列表、详情、删除和取消行为保持现状）。
- [ ] 自动巡检调度、评分和告警逻辑没有行为变化（验证：差异不包含相关执行逻辑修改，后端现有调度和报告测试通过）。
- [ ] SQLite 测试环境和 PostgreSQL 使用的查询表达式均兼容（验证：不使用数据库专属 JSON 函数和迁移；SQLAlchemy 测试在 SQLite 通过）。
