# 自动巡检分页与全局异常置顶 Spec

## 背景

自动巡检日志使用服务端分页。当前用户点击较后页码时，页面可能先发起目标页查询，又因旧查询结果或短暂空结果触发页码校正，导致目标页立即跳回第 1 页。该问题使大量历史日志无法可靠浏览。

页面已有单条任务内的 Kiro 身份泄漏和 Thinking Signature 错误提示，但异常只在对应任务数据已加载并展开时可见。用户需要逐页、逐条查找，不能在自动巡检日志区域顶部立即看到跨页异常。

## 方案选择

- 推荐方案：分页状态只在用户切换筛选、每页条数或数据删除后确实越界时校正；正常点击有效页码时保持目标页。后端在当前筛选范围内提供轻量级异常摘要，页面在日志区域顶部展示明确 Kiro 身份泄漏和明确 Thinking Signature 拒绝，并允许进入对应记录详情。该方案能跨全部分页准确汇总，也不会恢复逐条请求造成的查询性能问题。
- 备选方案：前端逐页拉取全部日志，再逐条加载详情并统计异常。实现直观，但会产生大量请求，289 页数据下性能和稳定性不可接受。
- 不采用：只汇总当前页异常。改动较小，但用户仍需逐页查找，不满足“直接在顶部展示”的目标。

## 目标

- 点击任意有效页码后稳定显示目标页，不再自动跳回第 1 页。
- 在自动巡检日志顶部跨全部分页展示明确 Signature 和 Kiro 异常。
- 异常摘要提供命中数量和可定位入口，用户无需逐页展开查找。
- 保持运营故障与真实性异常的边界，不把权限、配额、网络、超时或服务错误置顶为 Signature/Kiro 异常。

## 功能需求

- F1: 用户点击有效页码后，分页器保持该页，表格显示该页日志；加载过程不得使用上一页或短暂空结果把页码重置为 1。
- F2: 用户点击上一页、下一页、首尾页或数字页码时，分页器、请求页码和表格内容必须一致。
- F3: 只有渠道筛选改变、每页条数改变、删除导致总页数缩减，或服务端确认目标页越界时，页面才校正页码；筛选和每页条数改变时回到第 1 页，越界时进入最后一个有效页。
- F4: 自动巡检日志区域顶部展示当前渠道筛选范围内、跨全部分页的明确 Kiro 身份泄漏异常数量。
- F5: 自动巡检日志区域顶部展示当前渠道筛选范围内、跨全部分页的明确 Thinking Signature 拒绝数量。明确拒绝仅指 HTTP 400 且错误为 `Invalid signature in thinking block`，或等价的结构化明确拒绝证据。
- F6: 顶部异常摘要按 Kiro 和 Signature 分开显示；两类同时存在时均可见，没有命中时不显示对应提示。
- F7: 每类异常摘要至少提供命中任务入口；点击后可进入对应巡检详情并查看 Request ID、HTTP 状态、阶段及脱敏错误证据。命中较多时允许展示有限数量入口和总数，但不能只展示当前页命中。
- F8: 切换渠道筛选后，异常摘要同步为该渠道范围；切换“只看错误”不改变真实性异常的统计口径，只改变日志表格范围。
- F9: 权限禁止、账号或模型不可用、配额不足、网络失败、超时、HTTP 5xx、临时不可用及其他运营故障不计入顶部 Signature/Kiro 异常。
- F10: 顶部摘要不得改变巡检状态、评分、错误筛选、删除范围、排序和调度执行行为。

## 非功能需求

- N1: 异常汇总必须使用轻量数据，不恢复按日志逐条请求完整结果的查询方式；日志数量增长时，首页请求量不得随总页数线性增长。
- N2: 异常判定继续以结构化标签和明确协议证据为主，历史文本兼容只能识别明确 Kiro 身份自报和明确 Signature 拒绝，不能仅因正文出现 `kiro` 或 `signature` 单词而命中。
- N3: 顶部仅展示脱敏摘要和诊断标识，不展示 API Key、鉴权头、完整 Thinking Signature 或敏感原始响应。
- N4: 保持 SQLite 本地开发和 PostgreSQL 部署兼容，不新增队列、缓存服务或数据库迁移。
- N5: 保留工作区现有未提交改动，不覆盖或混入本需求之外的删除保护和其他并发修改。
- N6: 必须通过真实分页交互测试验证，不得仅以页码状态函数的单元测试作为完成证据。

## 不做的事

- 不置顶展示所有运营错误或普通 HTTP 400。
- 不把任何出现 `signature` 或 `kiro` 字样的记录直接判为异常。
- 不自动删除、重跑、禁用或切换异常渠道。
- 不修改普通检测任务列表的分页和异常展示。
- 不在本需求中改变自动巡检调度频率、告警发送或评分规则。

## 验收标准

- AC1: 准备至少 60 条巡检日志，点击第 6 页后分页器稳定停在第 6 页，表格显示第 6 页记录；等待查询完成和一次轮询后仍不跳回第 1 页。
- AC2: 从第 6 页依次点击上一页、下一页、第 1 页和末页，每次请求页码、分页器页码和可见记录均一致。
- AC3: 在第 6 页切换渠道或每页条数后回到第 1 页；删除数据导致当前页越界后进入最后一个有效页，不出现空白页或错误跳回第 1 页。
- AC4: 在不同分页分别放置 Kiro 身份泄漏记录，页面顶部显示跨页总数；切换到只包含部分命中的渠道后，总数同步缩小。
- AC5: 在不同分页分别放置明确 Thinking Signature 拒绝记录，页面顶部显示跨页总数，并与 Kiro 异常分开显示。
- AC6: 点击顶部 Kiro 或 Signature 异常入口后进入对应巡检详情，可查看脱敏的 Request ID、HTTP 状态、阶段和错误证据。
- AC7: 构造权限禁止、账号无权、配额不足、超时和 HTTP 5xx 记录，顶部 Kiro/Signature 异常数量均不增加。
- AC8: 仅在普通正文中讨论 Kiro 或 Signature、但没有明确身份自报或协议拒绝时，不显示顶部异常。
- AC9: 加载首页和切换分页时，不产生按全部日志逐条请求完整结果的请求风暴；请求数量保持为分页列表及固定数量的汇总请求。
- AC10: 后端相关测试、前端全量测试、TypeScript 编译、生产构建、差异格式检查和真实浏览器分页验收全部通过。
