# 自动巡检日志按渠道筛选 Spec

## 背景

运行记录页的“自动巡检日志”目前展示所有渠道的巡检记录。渠道较多时，需要人工在列表中查找同一渠道的记录，难以快速判断某个渠道是否持续出现异常。每条巡检日志已经带有可识别的渠道信息，因此只需要增加列表筛选行为即可改善排查效率。

## 目标

- 在“自动巡检日志”区域按渠道名称筛选日志。
- 让用户能够快速查看某个渠道的巡检结果、复审状态和详情入口。
- 保持现有日志加载、分页、展开详情、删除和查看详情行为不变。

## 功能需求

- F1: “自动巡检日志”区域提供渠道筛选控件，默认显示全部渠道，并列出当前已加载巡检日志中可识别的渠道名称。
- F2: 用户选择某个渠道后，自动巡检日志表格只显示该渠道的记录；表格中的巡检结果、复审、计划、时间、展开详情和删除操作继续针对原始日志工作。
- F3: 用户清除筛选或切回“全部渠道”后，表格恢复显示所有自动巡检日志。
- F4: 筛选结果为空时，表格显示明确的“当前筛选条件下无自动巡检日志”提示，而不是误显示为系统无日志。

## 非功能需求

- N1: 筛选应在现有已加载日志数据上即时完成，不新增数据库字段、不持久化 API Key 或其他敏感信息。
- N2: 渠道选项名称应稳定、可读；同一渠道只出现一个选项，并对缺失渠道信息的历史日志提供可选的“未识别渠道”归类。
- N3: 不改变自动巡检日志的默认排序、分页、轮询刷新和现有删除/详情交互。

## 不做的事

- 不为普通检测任务列表增加渠道筛选。
- 不增加后端查询参数、数据库迁移或新的渠道管理能力。
- 不同时改造智能巡检报告、复审告警筛选或渠道结果总览的筛选逻辑。

## 验收标准

- AC1: 打开运行记录页并定位到“自动巡检日志”时，能看到默认值为“全部渠道”的渠道筛选控件，选项来自当前日志中的渠道名称且无重复。
- AC2: 选择一个渠道后，自动巡检日志表格中的每一行都属于该渠道；展开详情、查看详情、删除日志仍能作用于对应原始记录。
- AC3: 清除渠道筛选后，自动巡检日志表格恢复显示未筛选时的全部记录和原有顺序。
- AC4: 选择没有匹配记录的渠道状态时，表格显示“当前筛选条件下无自动巡检日志”；没有筛选且确实无日志时，仍显示原有“暂无自动巡检日志”提示。
- AC5: 现有前端类型检查、构建和相关测试通过，且不影响运行记录页其他列表与操作。
