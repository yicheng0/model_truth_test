# 自动巡检日志按渠道筛选 Plan

## 架构概览

采用前端本地筛选方案：运行记录页继续通过现有运行记录接口加载全部数据，在页面状态中保存当前渠道筛选值，再从已拆分出的自动巡检日志集合计算可见行。筛选只影响“自动巡检日志”表格，不影响普通检测任务、渠道总览或后端数据。

```text
现有 runs 查询
  -> splitRunsByPatrol
  -> 提取巡检日志渠道选项
  -> 当前渠道筛选值
  -> filteredPatrolRuns
  -> 自动巡检日志表格
```

## 核心数据结构

### PatrolChannelFilterOption

- `value: string`：渠道 ID；历史记录无法识别渠道时使用固定的未识别值。
- `label: string`：表格中展示的可读渠道名称。

### PatrolRunFilterState

- `selectedChannelId: string`：当前筛选渠道，默认使用全部值；清除时恢复全部。
- `filteredPatrolRuns: Run[]`：按 `selectedChannelId` 过滤后的巡检日志，保持原始接口顺序。

## 核心接口

### 巡检渠道识别与筛选工具

在运行记录相关工具中提供纯函数，用于：

1. 从巡检日志提取稳定且去重的渠道选项，优先使用日志的渠道 ID 和显示名称。
2. 对缺失渠道信息的历史日志归入“未识别渠道”。
3. 根据全部值、渠道 ID 或未识别值过滤巡检日志。

纯函数不修改输入数组，便于单元测试和页面复用。

## 模块设计

### 运行记录页面

**职责：** 保存渠道筛选状态，渲染筛选控件，计算可见巡检日志，并把可见集合用于表格数据源、空状态和已选行清理。

**交互：** 在“自动巡检日志”卡片操作区放置 `Select`，提供“全部渠道”、去重后的渠道名称和必要的“未识别渠道”选项；选择变化立即更新表格。删除日志成功后沿用现有缓存更新，筛选状态不被意外重置。

**边界：** 若刷新后当前选中的渠道已不再出现在日志中，保留筛选值并显示无匹配提示；用户可通过清除按钮恢复全部。默认无筛选时继续显示“暂无自动巡检日志”。

### 运行记录工具模块

**职责：** 集中渠道标签生成、选项去重和过滤条件判断，避免 JSX 中重复处理历史字段缺失和显示名称格式化。

### 测试模块

**职责：** 覆盖选项去重、未识别渠道归类、按渠道过滤、全部/空结果边界，并保留现有运行记录工具测试。

## 模块交互

1. `Runs` 页面收到 `runs.data` 后调用现有 `splitRunsByPatrol`。
2. 工具函数扫描 `patrolRuns` 生成筛选选项；选项按可读名称排序，全部值固定置顶。
3. 页面以当前选择调用过滤函数，得到 `filteredPatrolRuns`。
4. 表格 `dataSource`、勾选行有效性清理和空状态判断使用过滤后的集合；详情查询仍使用每行原始 `run.id`。
5. 轮询或删除导致数据更新时重新计算选项和可见集合，不发起额外请求。

## 文件组织

```text
frontend/src/
├── runsUtils.ts                 # 新增巡检渠道选项与过滤纯函数
├── runsUtils.test.ts            # 新增渠道筛选单元测试
└── pages/Runs.tsx               # 新增筛选状态、控件、可见日志数据源和空状态
```

不修改后端文件、API 类型、数据库迁移或其他页面。

## 技术决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 筛选位置 | 前端已加载数据 | 日志列表数据量已有分页展示规模；无需改接口，交互即时且风险小 |
| 筛选主键 | 渠道 ID | 同名渠道仍可区分，避免仅按名称误合并 |
| 展示名称 | 复用现有巡检渠道格式化逻辑 | 保持日志表格与详情中的渠道命名一致 |
| 历史缺失数据 | 固定归类“未识别渠道” | 不丢弃旧日志，并满足可观测边界行为 |
| 选项排序 | “全部渠道”置顶，其余按名称排序 | 便于定位，同时避免随接口返回顺序抖动 |
| 后端改动 | 不增加 | 本次需求只要求查看已加载日志，避免扩大查询和迁移范围 |
| URL 持久化 | 不增加 | 规格未要求跨刷新保留，保持实现简单 |
