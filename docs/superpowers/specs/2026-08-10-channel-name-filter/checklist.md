# 自动巡检日志按渠道筛选 Checklist

> 每项均通过运行代码或观察行为验证。

## 实现完整性

- [x] 自动巡检日志区域显示渠道筛选控件，默认显示“全部渠道”，选项按渠道标识去重并使用可读名称（验证：打开 `/runs`，DOM 显示“自动巡检日志渠道筛选”和“全部渠道”；`runsUtils.test.ts` 覆盖选项去重）。
- [x] 选择指定渠道后仅显示该渠道的巡检日志，并保持每行原有巡检结果、复审、计划、时间、展开和详情操作（验证：筛选纯函数测试确认只返回指定渠道且保留原始顺序；表格仍使用原始 `run.id` 操作）。
- [x] 清除筛选或切回“全部渠道”后恢复全部日志及原始顺序（验证：筛选纯函数测试覆盖全部值返回全部 ID 和原顺序；Select 清除回到全部值）。
- [x] 缺失渠道信息的历史日志可归入“未识别渠道”并可筛选（验证：`runsUtils.test.ts` 覆盖无渠道 ID/名称日志）。

## 集成

- [x] 运行记录轮询刷新或删除日志后，筛选结果与可见行选择状态同步更新，未发起额外筛选请求（验证：筛选为本地 `useMemo` 计算，未新增 API 调用；构建通过）。
- [x] 普通检测任务列表、渠道结果总览和其他页面行为不受渠道筛选影响（验证：改动仅接入 `filteredPatrolRuns` 到自动巡检日志表格；完整测试通过）。

## 空状态与边界

- [x] 指定渠道无匹配日志时显示“当前筛选条件下无自动巡检日志”（验证：过滤函数单元测试覆盖无匹配返回空数组，页面空状态按筛选值分支）。
- [x] 未选择渠道且系统确实没有巡检日志时显示“暂无自动巡检日志”（验证：本地 `/runs` DOM 实测显示该文案）。
- [x] 全部值、空数组、无匹配渠道和重复渠道名称均有稳定结果，且过滤函数不修改输入数组（验证：`runsUtils.test.ts`）。
