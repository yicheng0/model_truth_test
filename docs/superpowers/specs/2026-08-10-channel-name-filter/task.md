# 自动巡检日志按渠道筛选 Tasks

## 文件清单

| 操作 | 文件 | 职责 |
|---|---|---|
| 修改 | `frontend/src/runsUtils.ts` | 增加巡检渠道筛选常量、渠道选项提取和日志过滤纯函数 |
| 修改 | `frontend/src/runsUtils.test.ts` | 覆盖渠道选项、去重、未识别渠道和过滤边界 |
| 修改 | `frontend/src/pages/Runs.tsx` | 增加筛选状态、Select 控件、过滤后的表格数据源和空状态 |

## T1: 定义巡检渠道筛选工具

**文件：** `frontend/src/runsUtils.ts`

**依赖：** 无

**步骤：**
1. 定义全部渠道和未识别渠道使用的固定值与展示文案。
2. 根据巡检日志的渠道 ID、渠道名称及现有格式化规则生成稳定渠道标签。
3. 实现渠道选项提取函数：按渠道 ID 去重，缺失渠道信息时归入未识别渠道，全部选项置顶，其余按展示名称排序。
4. 实现日志过滤函数：全部值返回原顺序副本；指定渠道按渠道 ID 筛选；未识别值只匹配缺失渠道信息的日志。
5. 保证输入数组不被修改，并保持 `Run` 类型兼容。

**验证：** 运行 `cd frontend && npm test -- --run runsUtils.test.ts`，新增测试未完成前允许暂不通过，完成 T2 后必须全部通过。

## T2: 添加渠道筛选工具测试

**文件：** `frontend/src/runsUtils.test.ts`

**依赖：** T1

**步骤：**
1. 构造两个渠道相同但名称不同或重复出现的巡检日志，验证选项只保留一个渠道。
2. 构造缺少渠道 ID/名称的历史日志，验证出现一个“未识别渠道”选项且相关日志可被筛选。
3. 验证指定渠道只返回该渠道日志，并保持原始顺序。
4. 验证全部值返回所有日志，空数组和无匹配渠道返回空数组。
5. 验证工具函数不会修改输入日志数组。

**验证：** 运行 `cd frontend && npm test -- --run runsUtils.test.ts`，期望现有测试和新增测试全部通过。

## T3: 在运行记录页接入筛选控件

**文件：** `frontend/src/pages/Runs.tsx`

**依赖：** T1

**步骤：**
1. 引入渠道选项提取和日志过滤工具，新增默认“全部渠道”的本地状态。
2. 基于当前 `patrolRuns` 计算渠道选项和 `filteredPatrolRuns`，不改变原始 `patrolRuns`。
3. 在“自动巡检日志”卡片操作区增加渠道 `Select`，支持清除并回到全部渠道。
4. 将日志表格数据源、筛选后的行选择清理和可删除数量计算改为使用可见日志集合，同时保持删除 mutation 使用原始日志 ID。
5. 根据是否有筛选条件区分“暂无自动巡检日志”和“当前筛选条件下无自动巡检日志”两种空状态。
6. 保持展开详情、查看详情、复审状态、轮询刷新、分页和普通检测任务列表行为不变。

**验证：** 运行 `cd frontend && npm run build`，期望 TypeScript 检查和 Vite 构建成功。

## T4: 执行回归验证

**文件：** 无新增文件；检查 T1-T3 改动

**依赖：** T2、T3

**步骤：**
1. 运行前端完整测试，确认运行工具及其他页面测试无回归。
2. 启动前端开发服务，打开运行记录页，确认自动巡检日志筛选控件、选项和空状态。
3. 选择一个渠道，确认仅显示该渠道日志，并打开一条详情验证原始 run ID 链接。
4. 清除筛选，确认日志数量和顺序恢复。

**验证：** 运行 `cd frontend && npm test && npm run build`；必要时使用浏览器检查 `/runs`，期望命令成功且端到端行为符合 AC1-AC4。
