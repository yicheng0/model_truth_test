# Signature 完整展示 Spec

## 背景

当前模型请求详情中的原始响应会把 thinking block 的 `signature` 只保留前 50 个字符并追加省略号。用户查看“原始响应”时无法核对或复制完整 Signature，页面名称与实际展示内容不一致，也削弱了协议证据的可复核性。

## 目标

- 在原始请求与原始响应证据中完整展示并允许复制 thinking Signature。
- 摘要、列表和“Signature 前缀”等紧凑区域继续只展示短前缀，保持页面可扫描性。
- 不扩大认证凭证和其他敏感字段的展示范围。

## 功能需求

- F1: 新产生的模型请求记录在“原始请求”和“原始响应”区域展示上游实际返回或复用的完整 thinking Signature，不主动添加省略号或截断字符。
- F2: 完整 Signature 必须能够通过原始证据区域完整选中或复制，长内容允许换行或滚动，但不得覆盖其他界面内容。
- F3: Signature 摘要、列表、报告概览及明确标为“Signature 前缀”的区域继续展示短前缀，不因本次变更展开成长文本。
- F4: API Key、认证头、令牌、密码及其他既有敏感字段继续按当前规则脱敏，不得因完整展示 Signature 而恢复或暴露。
- F5: 已经持久化为截断文本的历史记录保持可读，但系统不伪造或推断其缺失部分；只有保留了完整值的新记录才完整展示。

## 非功能需求

- N1: 不改变 Source 生成 Signature、官方 Relay 验证 Signature 的检测方向和判断语义。
- N2: 不改变 Signature 互通评分、异常标签、运行状态或报告结论。
- N3: 长 Signature 的展示不得造成页面横向撑开、文本重叠或操作区域位移。
- N4: 修改须有自动化回归测试，验证完整值不被截断，同时验证认证凭证仍被脱敏。

## 不做的事

- 不恢复历史记录中已经丢失的 Signature 后缀。
- 不在任务列表、巡检摘要或报告概览中直接展开完整 Signature。
- 不修改 Signature 生成、加密、验证或跨渠道复用协议。
- 不新增下载、导出、搜索或 Signature 解码功能。

## 验收标准

- AC1: 使用长度超过 50 个字符的 Signature 生成一条新模型请求记录后，原始响应展示的值与上游返回值逐字符一致，且没有人工追加的省略号。
- AC2: Relay 原始请求包含长度超过 50 个字符的 Signature 时，页面完整展示该值并可完整复制。
- AC3: 相同记录在“Signature 前缀”或摘要区域仍只显示短前缀，不展开完整值。
- AC4: 在包含 API Key、Authorization 或令牌字段的测试数据中，原始证据仍不展示真实凭证值。
- AC5: 长 Signature 在桌面端和窄屏布局中均通过换行或滚动完整查看，不与相邻内容重叠。
- AC6: Signature 检测语义、标签与评分的相关回归测试通过，前端生产构建通过。
