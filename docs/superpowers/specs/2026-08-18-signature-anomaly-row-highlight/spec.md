# Signature 异常巡检行同步高亮 Spec

## 背景

自动巡检日志顶部已经集中展示“Thinking Signature 无效”及对应任务入口，但下方巡检表格中的异常任务仍与普通异常使用相同的白色行背景。用户在当前分页查看多条异常记录时，无法快速区分哪些行对应顶部 Signature 无效提示，需要逐条核对任务名称或进入详情。

## 目标

- 顶部明确列出的 Thinking Signature 无效任务，在下方自动巡检表格中同步使用醒目的特殊颜色。
- 用户无需展开行或进入详情，即可在当前页快速定位对应的 Signature 异常任务。
- 继续沿用现有严格 Signature 异常口径，不扩大异常范围。

## 功能需求

- F1: 当一条自动巡检任务出现在顶部“Thinking Signature 无效”异常集合中，且该任务同时出现在下方当前分页时，对应整行必须显示浅红色背景高亮。
- F2: 高亮匹配必须基于同一巡检任务标识，不能仅按渠道名称、任务名称、普通异常状态或“需要复审”状态判断。
- F3: 普通模型探针异常、Kiro 身份泄漏、运行失败、权限、网络、超时、配额及其他运营故障不得获得本次 Signature 专属行高亮，除非同一任务也明确属于 Thinking Signature 无效集合。
- F4: 切换渠道、页码、每页条数或异常筛选后，高亮必须随顶部异常数据和当前表格数据同步更新。
- F5: 行高亮不得影响现有行展开、复选、查看详情、取消、删除、悬停和选中行为。

## 非功能需求

- N1: 使用与顶部错误提示一致的浅红色语义，文字、标签和操作按钮保持清晰可读。
- N2: 不新增后端接口、数据库字段或额外的任务详情请求。
- N3: 保持现有严格异常判定边界：只有明确的 Thinking Signature 拒绝才进入该集合，运营不确定性不染色。
- N4: 通过前端自动化测试和生产构建验证，并覆盖高亮、非高亮及数据更新场景。

## 不做的事

- 不修改顶部异常提示的数量、内容、排序或跳转行为。
- 不改变 Kiro 身份泄漏、普通巡检异常或“需要复审”的现有颜色。
- 不修改 Signature 检测、评分、报告、告警或飞书通知逻辑。
- 不为不在当前分页中的任务自动翻页或滚动。
- 不重新设计自动巡检表格的列、间距或操作区。

## 验收标准

- AC1: 顶部“Thinking Signature 无效”包含某任务，且该任务位于当前分页时，该任务整行显示浅红色背景。
- AC2: 当前页存在普通异常、Kiro 异常、运营故障或需要复审任务，但它们不在 Signature 无效集合时，对应行不显示 Signature 专属浅红色背景。
- AC3: 同一渠道存在多个同名任务时，只高亮任务标识与顶部 Signature 异常条目一致的行。
- AC4: 切换渠道、页码、每页条数或“只看错误”后，当前可见行按照最新异常集合正确增加或移除高亮。
- AC5: 高亮行仍可正常展开、选择、进入详情、取消或删除；文本与按钮在默认和悬停状态下均清晰可见。
- AC6: 页面不新增任务详情请求，前端相关测试和生产构建均通过。
