# Signature 异常巡检行同步高亮 Checklist

> 每项均通过运行代码或观察页面行为验证。

## 实现完整性

- [x] 顶部 Signature 异常分组中的任务 ID 能归一为唯一集合（验证：传入多个、重复、空值和缺失 ID，期望只得到有效唯一 ID）。
- [x] Signature 异常任务出现在当前分页时整行显示专属浅红背景（验证：打开自动巡检日志并检查对应表格行 class 与视觉背景）。
- [x] 任务 ID 不在 Signature 异常集合时不显示专属高亮（验证：检查普通异常、Kiro、运营故障和仅需复审的行）。
- [x] 同名不同 ID 的任务不会被错误一起高亮（验证：fixture 中使用相同名称的不同任务，检查只有 ID 命中的行获得 class）。
- [x] Signature 异常集合为空、查询无数据或查询失败时不残留旧高亮（验证：页面 error 状态显式使用空集合；无 Signature 渠道 E2E 通过）。
- [x] 高亮行 hover 后仍保持可识别的浅红色语义，文字、标签和操作按钮可读（验证：悬停高亮行并检查计算样式与文本可见性）。

## 集成

- [x] 顶部 “Thinking Signature 无效” 与下方表格使用同一异常摘要数据（验证：顶部任务链接的 `run_id` 对应表格高亮行）。
- [x] 切换渠道后高亮集合与表格数据同步刷新（验证：渠道 A 的 Signature 行高亮，切换渠道 B 后该行不再可见或不再高亮）。
- [x] 切换“只看错误”、分页和每页条数后高亮状态按当前可见数据更新（验证：切换筛选和页码，检查命中行 class 始终与摘要集合一致）。
- [x] 删除或取消任务后既有查询失效机制同步移除对应高亮（验证：操作任务后刷新表格和异常摘要，检查已移除任务不再高亮）。
- [x] 页面不为高亮增加任务详情请求（验证：记录网络请求，首屏及筛选切换不新增 `/results` 详情请求）。
- [x] 行展开、复选、查看详情、取消和删除功能保持可用（验证：对高亮行逐项执行现有操作，行为与普通行一致）。
- [x] 不修改顶部异常数量、排序、文案或详情跳转（验证：运行现有顶部异常断言，检查文本与链接保持不变）。

## 编译与测试

- [x] 归一函数测试先红后绿（验证：实现前聚焦测试因函数不存在失败，实现后同一命令通过）。
- [x] 前端完整单元测试通过（验证：`npm test -- --run`，20 个测试文件、179 个用例通过）。
- [x] 前端生产构建通过（验证：`npm run build`，TypeScript 和 Vite 均退出码为 0）。
- [x] 浏览器巡检分页回归通过（验证：`node e2e/runs-pagination.mjs`，高亮、筛选、分页、删除和详情断言全部通过）。
- [x] 差异无空白错误（验证：仓库根目录运行 `git diff --check`，无输出）。
- [x] 改动范围受控（验证：差异仅包含本次前端测试、工具、页面、样式和 E2E 文件；已有无关改动保持原样）。

## 端到端场景

- [x] 明确 Signature 拒绝任务 -> 打开自动巡检日志 -> 顶部显示 Signature 异常 -> 当前页对应任务整行浅红高亮 -> 点击详情仍能查看完整证据（验证：浏览器 fixture 流程）。
- [x] 同页混合 Signature、Kiro、普通异常和运营故障 -> 只有严格 Signature 集合中的任务获得专属高亮（验证：逐行检查 class 和颜色）。
- [x] 同名任务但 ID 不同 -> 只有顶部异常条目对应的任务高亮（验证：浏览器或单元测试 fixture）。
- [x] 切换到没有 Signature 异常的渠道 -> 顶部 Signature 提示消失 -> 当前表格无 Signature 专属高亮 -> 普通巡检日志仍可操作（验证：浏览器筛选流程）。
- [x] Signature 摘要请求延迟或失败 -> 普通表格仍可展示和操作 -> 不出现错误的旧高亮（验证：错误状态代码路径使用空集合；构建与回归通过）。
