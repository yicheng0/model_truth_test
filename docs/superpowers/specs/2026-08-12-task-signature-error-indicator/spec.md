# 任务列表 Signature 错误提示 Spec

## 背景

部分渠道请求会返回 HTTP 400，并在错误内容中出现 `Invalid \`signature\` in \`thinking\` block`。当前任务列表没有针对该明确协议错误的条件提示，用户需要展开任务详情并自行查找原始错误。

## 目标

- 在任务列表中快速提示该类明确的 Signature 协议错误。
- 没有命中该错误时不增加任何提示、标签或噪声。
- 保留 Request ID，便于继续定位上游请求。

## 功能需求

- F1: 当任务结果中存在 HTTP 状态码 400，且错误文本包含 `Invalid \`signature\` in \`thinking\` block`（大小写不敏感）时，任务列表显示 Signature 错误提示。
- F2: 提示中至少展示错误类型和可用的 Request ID；多个匹配结果的 Request ID 去重并稳定展示。
- F3: 当状态码不是 400、错误文本不匹配、结果无错误或任务尚未完成时，任务列表不显示该提示。
- F4: 该提示不改变任务状态、评分、删除/取消操作和现有详情链接。

## 非功能需求

- N1: 复用现有任务结果接口和脱敏后的结构化结果，不新增 API Key、请求头或敏感原始信息展示。
- N2: 错误识别集中在可测试的纯函数中，兼容错误可能位于 normalized response、raw response 或 metrics 的现有结构。
- N3: 不把其他 Signature 失败、网络失败或普通 400 错误误标为该提示。

## 不做的事

- 不修改后端错误分类、报告评分和巡检告警规则。
- 不展示所有 400 错误，不新增重试、弹窗或自动跳转。
- 不改变任务详情页现有原始响应查看方式。

## 验收标准

- AC1: 构造状态码 400 且错误文本匹配的结果后，任务列表显示 Signature 错误提示和对应 Request ID。
- AC2: 构造状态码非 400、文本不匹配和无错误结果后，任务列表均不显示该提示。
- AC3: 多条匹配结果只显示一次错误类型，并按稳定顺序展示去重后的 Request ID。
- AC4: 任务列表原有状态、评分、操作和详情链接保持不变，前端测试与构建通过。
