# 自动巡检日志直接展示错误 Plan

## 架构概览

本次改动限定在前端自动巡检日志的数据归一化辅助逻辑和列表紧凑展示。后端现有运行详情接口已经返回脱敏后的探针错误、响应文本、Signature 原始错误、HTTP 状态和异常说明，因此不新增接口或存储字段。

数据流为：

1. 运行详情响应转换为统一巡检证据。
2. 使用现有运营故障和 Signature 明确拒绝规则判定错误类型。
3. 从证据中提取最具体、可直接展示的错误正文及完整内容。
4. 列表紧凑模式在状态标签下显示截断后的错误正文。
5. Tooltip、展开行和详情页继续提供完整脱敏证据。

## 核心数据结构

### PatrolInlineError

- `kind`: `operational`、`signature`、`probe` 或 `load_failure`，用于样式和语义，不新增后端标签。
- `text`: 适合列表直接显示的精简正文。
- `fullText`: 完整脱敏错误，用于 Tooltip。
- `source`: 错误来自模型探针、Signature 证据、报告异常说明或详情加载失败。

### 错误选择优先级

同一条巡检证据可能同时包含多个错误来源，列表只展示一个主要错误，优先级如下：

1. 具体模型探针的 `error`。
2. 模型探针的错误响应正文。
3. Signature 的 `raw_error` 或 `reason`；只有明确 thinking block Signature 拒绝才标记为 `signature`。
4. 分类原因、报告摘要或标签说明。

若主要错误属于网络、超时、5xx、额度或资源池故障，则 `kind` 固定为 `operational`，即使文本中出现普通单词 `signature`。

## 核心接口

### 错误正文提取

在巡检工具模块增加纯函数，输入统一巡检证据，返回主要直接展示错误或 `null`。

规则：

- 正常证据且没有运营失败时返回 `null`。
- 运营错误可在整体显示状态为“正常/运营问题”时仍返回正文，因为用户需要直接看到请求失败原因。
- 明确 `Invalid signature in thinking block` 返回 Signature 类型。
- `signature validation timed out`、网络错误和 5xx 返回运营类型。
- 对标签兜底时优先使用已有中文解释，不直接把内部标签作为首选正文。
- 文本先压缩空白，完整文本不在纯函数中破坏；列表截断由展示组件负责。

### 紧凑错误展示

自动巡检结果紧凑单元格从单一横向标签容器改为上下两层：

- 第一层保留结果和探针标签。
- 第二层只在存在直接错误时显示一行危险色或运营警示色正文。
- 列表正文限制为两行或固定最大高度，支持长单词换行和省略。
- 整个错误正文带 Tooltip，展示完整脱敏内容。

详情加载失败分支不再只显示“日志加载失败”标签，而是直接附带可读错误原因。

## 模块设计

### `runsUtils`

**职责：** 统一判断错误类别并提取列表主要错误，复用现有运营故障判断和明确 Signature 拒绝表达式。

**对外接口：** 新增纯函数及返回类型；不修改后端响应类型。

**依赖：** 现有巡检证据类型、运营故障标签与错误文本规则。

### `Runs` 页面

**职责：** 在自动巡检结果紧凑单元格直接展示主要错误，并处理详情加载失败错误。

**对外接口：** 页面路由、查询键、分页、筛选和操作接口不变。

**依赖：** `runsUtils` 的直接错误提取结果、现有 Tooltip 和 Typography 组件。

### 样式

**职责：** 限制错误正文行数、高度和溢出，区分运营故障与真异常，同时保持紧凑表格可扫描。

**对外接口：** 仅增加巡检日志作用域内的样式类。

### 测试

**职责：** 纯函数测试覆盖错误选择和分类；浏览器交互测试使用固定巡检证据，验证错误无需操作即可在 DOM 和截图中可见，并覆盖分页后的行对应关系。

## 模块交互

```text
/api/runs/{id}/results
  -> extractPatrolEvidence
  -> patrolInlineError
       -> isPatrolOperationalFailure
       -> explicit Signature rejection matcher
  -> PatrolEvidenceSummary(compact)
       -> status/probe tags
       -> inline error text + full tooltip
```

## 技术决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 展示位置 | 巡检结果单元格标签下方 | 无需新增宽列，直接对应当前日志和探针状态 |
| 主要错误数量 | 列表只显示一个，详情保留全部 | 控制行高，适合快速扫描；完整证据仍可追踪 |
| 错误提取位置 | `runsUtils` 纯函数 | 分类与展示复用同一证据规则，可稳定单测 |
| 运营错误样式 | 警示正文但不标 Signature 失败 | 直接暴露故障，同时维持既有真实性判断边界 |
| Signature 类型 | 只接受明确 thinking block 拒绝 | 防止网络或超时文本含 signature 时误导 |
| 长文本 | 两行截断 + Tooltip 完整内容 | 保持列表密度并允许查看完整脱敏错误 |
| 后端变更 | 无 | 现有证据字段足够，减少范围和发布风险 |
